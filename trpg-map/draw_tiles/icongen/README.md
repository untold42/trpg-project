## 1. 硬规格（改这些会破坏地图）

| 项 | 值 | 说明 |
|---|---|---|
| 输出 | **每键一个文件夹，两个文件**：`public/mapicons/<键>/day.png` + `night.png` | 均 128×128 RGBA、透明底 |
| 内容占比 | 自适应留白到 **~100/128**，居中 | `fit_icon()` 自动做，别手调 |
| **日/夜** | `day` = 白天（窗不发光、整体更亮）；`night` = 夜里（**窗火 + 琥珀背光**） | 由前端按**游戏时辰**自动切（见 §1.5） |
| **key 必须三方一致** | `song_kinds.py` 的 `icon=` ↔ `manifest.txt` 键名 ↔ 文件夹名 | 对不上一律退化成**棕色圆点** |
| 实际显示尺寸 | **40 ~ 64px**（z15=40 / z16=48 / z17=56 / z18=64） | `iconSizeFor()` = `40 + (zoom-15)*8`，`Math.min(s,72)` 的上限**永远不触发** |
| 显示下限 | z15 起才显示 | `MIN_ICON_ZOOM = 15` |
| 底图纸色 | **`(238, 231, 207)`** | 实测自 `public/tiles/16/*/*.png` 的众数色 |

**因为最小只有 40px，一切设计按 40px 优先**：40px 下看不见的东西就不该画（见 §5）。

## 1.5 自动化管线与昼夜（`make_icons.py`）

全项目 **54 个 icon 键 / 2009 处布点**，每键两张图。两条来源：

| 来源 | 判据 | 日图 | 夜图 |
|---|---|---|---|
| **专属 render**（质量最高） | 键在 `buildings.BUILDINGS` 里 | `with_palette(DAY_PALETTE, fn)` | `fn()` 就是夜色 |
| **原型库**（覆盖全部其余键） | 键在 `archetypes.SPECS` 里 | 同上（同一份代码换色板） | 同上 |

**昼夜规则（重要）**：`DAY_PALETTE` **只改光照，不改材质** ——
石还是那个石、瓦还是那个瓦。变的只有：
1. 窗/门洞：夜里 `GLOW` 亮，白天换成未点灯的暗洞口；
2. 灯笼：夜里带暖光晕，白天是普通红灯；
3. 白昼另加**檐下日照投影**（`shadow_band`）—— 这是日图白天感的主要来源。

> 早先版本把砖瓦也一起调亮了，被用户指出「怎么把砖块的颜色也改了」→ 已纠正。
> 现在日/夜两张图的材质色**逐字节相同**，只有灯与影子不同。

**目录**：`catalog.md` / `catalog.json` 由 `song_kinds.py` 的 KINDS + `manifest.txt` 布点数量自动汇总，
列出每个键的场所名 / 功能大类 / 布点倾向 / 备注 —— **画图标前先读它**，那就是设计简令。

**前端怎么切昼夜**：

```
GameController(useIsNight)  →  <GameMap isNight>  →  <ClickableLayer isNight>
   时钟锚点 GET /clock，60s 轮询；卯~酉(3..9)为昼，戌~寅(10,11,0,1,2)为夜
   取图路径： /mapicons/<键>/{day|night}.png
```

> ⚠️ **`vite.config.ts` 给 `/mapicons/*` 设了 `max-age=31536000, immutable`**。
> 换了图之后**浏览器不会更新**，必须硬刷新（或改文件名/加查询串）才能看到新图。
> 调试图标时请先想到这一条，别怀疑生成错了。

## 2. 竖向排版模板（照抄这个骨架）

青楼那张图的坐标（128 逻辑空间），实测好用，新建筑直接改数值：

```
  y=25  鸱尾顶            ← 屋顶最高处，留 25 给天空
  y=30  正脊
  y=40  檐角（tip_y）      ← 比檐口中点高 → 翘角
  y=52  檐口中点（eave_center_y）
  y=48~72   二层墙身        ← 窗 y=54~68
  y=67~77   腰檐（base_y=72, sag=5, lift=6）← 檐口最低点约 77
  y=72~102  一层墙身        ← 门 y=86~102
  y=102~110 台基
  y=66      灯笼吊绳起点（= 腰檐角部高度）→ 灯身 71.5~81 → 流苏 83.5
```

两条硬经验：

- **屋顶总宽 > 腰檐宽 > 墙宽**，形成金字塔收分。青楼：屋顶 `half_w=40`、腰檐 `half_w=34`、墙 `40~88`（半宽 24）。
- **腰檐要压在墙身上沿**（青楼：一层墙顶 72，腰檐中段 74~78 压住它）—— 否则两层之间会漏出一条透明缝。

## 3. 南宋建筑形制速查

### 3.1 屋顶 —— `roof()` 一个函数覆盖全部形制

正面 2D 视角下，各种屋顶**只差在平脊长度与檐口曲度**，所以不用写多套：

```python
roof(d, cx, half_w, ridge_half, ridge_y, eave_center_y, tip_y, ribs=RIBS, ridge_bar=True, chiwei=True)
```

| 形制 | `ridge_half` | `tip_y` | 用在哪 | 附加 |
|---|---|---|---|---|
| **攒尖顶** | `0` | `< eave_center_y` | 亭 / 塔 / 阁 | 顶部加宝顶（金色菱形） |
| **庑殿顶** | `≈0.35 × half_w` | `< eave_center_y` | 殿 / 正堂（等级最高） | 正脊 + 鸱尾 |
| **歇山顶** | `≈0.22 × half_w` | `< eave_center_y` | 楼阁 / 厅堂（最常用） | 正脊 + 鸱尾；可加博风/山花 |
| **悬山 / 硬山** | `≥0.6 × half_w` | `≈ eave_center_y` | **民居 / 店铺 / 作坊** | 少瓦垄、无鸱尾 |
| **重檐** | — | — | 楼阁 / 城门楼 | `roof()` 画上层 + `eave()` 画下层 |

民居/店铺（未来最常画的一类）**不必用 `roof()`**，直接给梯形更省事、更像硬山：

```python
g = 3                                    # 山墙外扩
poly(d, [(x0, eave_y), (x0 - g, ridge_y), (x1 + g, ridge_y), (x1, eave_y)],
     fill=TILE, width=1.3)
seg(d, [(x0 - g, ridge_y), (x1 + g, ridge_y)], TILE_DK, 3.0)      # 正脊，就够了
```

**曲线原理**（想自己改参数时看）：

```python
d = clamp((|x-cx| - ridge_half) / (half_w - ridge_half), 0, 1)   # 0=正脊端 1=檐角
y_top = ridge_y   + (tip_y - ridge_y)        * d*(2-d)      # 举折：先陡后缓
y_bot = tip_y     + (eave_center_y - tip_y)  * (1-d)*(1+d)  # 檐口：角部上翘、中间微垂
```

- `d*(2-d)` = 《营造法式》「举折」的观感（快落缓收），**不要换成直线**，会立刻失去宋味。
- 上下缘在 `d=1` 汇于同一点 → 屋面自然收成尖角 + 飞檐翘角。
- `eave_band()` 是同一套曲线的**带状**版本，用于腰檐 / 披檐 / 雨篷 / 城门雨棚。

**屋面细节构件**（`roof()` 已内置，单独用时注意）：

| 构件 | 做法 | 坑 |
|---|---|---|
| 瓦垄 | 沿 `d` 取 3 个比例画竖线，`TILE_DK`，宽 1.0 | 比例直接用 `RIBS = (0.34, 0.58, 0.82)` |
| 正脊 | `TILE_DK` 横线，宽 3.2 | 太细会看不出是脊 |
| 檐口滴水 | 下缘描一道 `TILE_LT` | 这道亮边是檐口"翻出来"的关键 |
| **鸱尾** | 正脊两端小三角，**`fill=INK, outline=None`** | ⚠️ 南宋是**鳍状**不是龙吻；加描边会整块变黑（我第一版就废在这） |

### 3.2 台基 / 踏道 / 勾栏

```python
poly(d, [(32, 102), (96, 102), (100, 110), (28, 110)], fill=STONE_DK)   # 台基：上窄下宽梯形
# 踏道（台阶）：中间一段浅色梯形 + 2 条横线；不要画成"台基下面几条墨线"（叠上影会成一坨）
poly(d, [(56, 102), (72, 102), (75.5, 110), (52.5, 110)], fill=STONE)
# 勾栏（栏杆）：上枋 + 下枋 + 蜀柱；低模下 ≤4 根蜀柱，再多 40px 就是一坨红
```

### 3.3 柱 / 墙 / 斗拱

- **朱红柱**：宽 4~5，右缘压 1.3px `VERM` 暗部即有色体积感。一角一柱即可，中间不必加。
- **石砖墙**：`STONE` 平涂（**当前项目的美术基准是"石砖脏色"**，不是粉墙米白，见 §4）。
- **墙脚水渍**：`band(d, x0, 墙底-6, x1, 墙底, STONE_DK)`，**这是"脏/风化"的主要来源**。
  放在墙身之后、门窗之前 → 门窗自然压在渍线上。
- **斗拱**：低模下**不要画**。40px 下必然糊成一团，画了只会脏。

### 3.4 门窗

```python
window_glow(d, x0, y0, x1, y1, rose=None, mullions=0)   # 灯火窗
rect(d, 56, 86, 72, 102, fill=GLOW, width=1.3, radius=5.0)   # 券门（圆角=券顶）
```

| 形制 | 做法 | 何时用 |
|---|---|---|
| **直棂窗**（南宋典型） | 竖向窗棂，`mullions=1~2` | 楼阁、殿宇 |
| 格子门 | 竖 + 横棂 | 别在 40px 下用，会糊 |
| **券门** | `radius=5` 圆角矩形，填 `GLOW` | 店面、门洞 |
| 壸门 | 券门压扁 + 下缘平 | 台基、佛塔 |

⚠️ **窗棂密度**：`mullions` 超过 2，或线宽 <0.8，40px 下会把亮窗糊成暗块 —— 灯火感立刻消失。
窗棂颜色用 `VERM`（脏砖红）而不是 `INK`，糊了仍像窗棂。

### 3.5 点景物件（"这是什么场所"就靠这些）

| 物件 | 配方 | 用途 |
|---|---|---|
| 灯笼 | `lantern(d, x, hang_y)` 默认 8×9.5 | 夜景店招；**吊绳必须接到檐角**，否则悬空 |
| 匾额 | 一块 `VERM` 横板（19×6）+ 1 道示意笔画 | 店 / 楼 / 堂 |
| 幌子 / 酒旗 | 细杆 + 竖红布条 | 酒肆、茶坊 |
| **人影剪影** | 头（椭圆 4×4）+ 肩身（梯形，肩宽 6~7）+ 手臂（细线 1.2） | **场所识别度最高的手段**：窗里有人 = 有生意 || 幡 / 经幢 | 竖杆 + 三角幡 | 寺 / 观 |
| 拴马桩、水缸 | 小矩形 / 小椭圆 | 补充生活感（40px 下会消失，慎加） |

**人影尺寸教训**：肩宽 10~13 = 魁梧（用户会指出）；**肩宽 6~7 才像人**。

**人影必须有对比底衬（实测教训）**。教坊第一版把双舞者 + 大鼓放在大片 `STONE_DK` 台基上：
人影（亮度 72）对台基（105）对比仅 33 → **40px 下整个人被台基吞掉，什么都看不见**。
解法：给乐舞场面铺一个**亮底** —— 改成「明间敞开、堂内灯火通明」（一块大 `GLOW`），
人影压在亮底上（对比 72 vs 203），并把人物从 14 放大到 18。
> 通用法则：**放人影前先问“它衬在什么上面？”** 背景比人亮 80+ 或暗 80+ 才成立。
> 同理：如果场景需要暗背景（如舸面），人影就反过来改用亮色。

### 3.6 材料 → 配色对照

| 材料 | 色 | 用在哪 |
|---|---|---|
| 青瓦 | `TILE` / `TILE_DK` / `TILE_LT` | 所有屋顶 |
| 青砖 / 石砖 | `STONE` / `STONE_DK` | 墙身、台基 |
| 木（朱红） | `VERM` | 柱、门窗框、匾、栏杆 |
| 灯火 | `GLOW` | 窗、门洞（**全图唯一亮点**） |

| 墨线 | `INK` | 一切描边、剪影式附件 |

## 4. 色彩法则

### 4.1 色板结构：**1 墨线 + 2~3 中性 + 1~2 强调色**

色相**不要超过 6 个**。需要更多层次时，**加同一色相的深浅档，不要加新色相**。
青楼的青瓦就有 3 档（`TILE` / `TILE_DK` / `TILE_LT`），全是同一个色相。

### 4.2 实测亮度表（判断层次靠这个数值，不靠眼睛）

| 名称 | RGB | 亮度 | 距纸色 |
|---|---|---|---|
| `INK` 墨线 | `52,46,42` | 47.3 | 309.9 |
| `FIGURE` 人影 | `88,66,60` | 71.9 | 267.1 |
| `TILE_DK` 瓦暗 | `72,80,82` | 77.8 | 256.9 |
| `VERM` 砖红 | `140,82,68` | 97.7 | 226.1 |
| `TILE` 青瓦 | `98,106,108` | 103.8 | 212.2 |
| `STONE_DK` 石砖暗 | `112,104,90` | 104.8 | 213.8 |
| `LANTERN` 灯笼 | `158,88,70` | 106.9 | 213.6 |
| `ROSE` 胭脂 | `152,98,98` | 114.1 | 192.3 |
| `STONE` 石砖墙 | `144,134,118` | 135.2 | 161.8 |
| `TILE_LT` 瓦亮 | `134,144,146` | 141.2 | 148.7 |
| `GLOW` 窗火 | `232,200,142` | 203.0 | 72.3 |
| 纸底 | `238,231,207` | 230.4 | 0 |

### 4.3 三条可操作的规则

1. **分离度**：色与纸色的距离 **<40 就必须靠 `keyline` 救命**。
   早期粉墙 `218,209,190` 距纸仅 **34** → 白墙直接糊进宣纸；换石砖 `144,134,118`（距 162）后才安全。
2. **窗内三层色阶**（青楼实测，风月/室内场景都适用）：
   `窗火 203 > 纱帘 114 > 人影 72` —— 亮窗里的暗帘、更暗的人，层次一出来"有人"才成立。
   ⚠️ 换暗墙色时**必须重算**：我从粉墙换石砖后，纱帘 `176,128,122`（亮度 142）和石墙 135 撞了，
   帘子直接消失，只好改成逆光深玫瑰 `152,98,98`。
3. **"脏" = 降明度 + 灰化色相，不是降纯度**。
   米白 v3 → 石砖 v4：亮度 120 → 97（−19%），而**纯度 22% 不变**。
   只降纯度会变"灰白"，不是"脏石"。

## 5. 低模原则（本项目审美基准）

这个游戏是低模风，**用户明确嫌过"细节太多"和"低模过头"两个极端**。落点：

| 指标 | 基准值 |
|---|---|
| 绘制调用数 | **~55**（`render_qinglou` 实测，量法见下）；调参方向是**变少、变大** |
| 色相数 | **≤6** |
| 平均纯度 | **~22%** |
| meanL | **95 ~ 120** |
| 描边宽度 | **1.0 ~ 1.4**（逻辑空间）；<0.8 在 40px 下消失 |
| 最小形状 | **≥3px**（再小会被描边吃掉，见 §8.2） |

**40px 判据**：画任何细节前问自己"它在 40px 下还剩几个像素？"
- 40px = 128 的 1/3.2 → 一个 6px 的构件在图上只有 **1.9px**。
- 瓦垄（1px 线）在 40px 下是 **0.3px** —— 它的作用只是"屋顶别太空"，不是让人看清瓦。
- 所以细节可以留，但**必须是大色块上的浅纹**，不能是独立小构件。

**「低模程度」的可复现量法**（调参时用它盯住自己有没有越画越碎）：

```python
import kit, buildings
from PIL import ImageDraw
n = 0
for name in ("polygon", "line", "rectangle", "rounded_rectangle", "ellipse"):
    orig = getattr(ImageDraw.ImageDraw, name)
    def wrap(orig=orig):
        def f(self, *a, **k):
            global n; n += 1
            return orig(self, *a, **k)
        return f
    setattr(ImageDraw.ImageDraw, name, wrap())
buildings.render_qinglou()
print("绘制调用数 =", n)      # 55
```

> 亲历教训：v1（细节版）用户说"**低模过头**"是错判——那是 v1 细节太多；
> 砍到 v2（纯色块、无屋脊瓦垄）用户又说"**低模过头了，屋顶细节加一下**"。
> 正确落点在中间：**大色块打底 + 屋面留 3~5 道浅纹**。

## 6. 标准工作流（7 步）

1. **定 key**：查 `trpg-map/draw_tiles/song_kinds.py` 找到该 kind 的 `icon=` 值 → 那就是文件名。
2. **抄模板**：在 `buildings.py` 加 `render_xxx()`，用 §2 的竖向骨架起稿。
3. **迭代**：`python gen_map_icons.py xxx --preview --small 40`，反复看图改坐标。
4. **校排版**：`--scan 58,88`（关键 y 值）确认每个构件的 x 区间正确、没重叠、没悬空。
5. **比指标**：`--stats` 与 §5 基准值对比（太暗/太花一眼看出）。
6. **给人看**：`--sheet` 出图 + **问用户 2~3 个具体问题**（见 §12）。
7. **落盘**：`--backup --sheet`，然后 `python selftest.py`（确认资产与代码一致）。
   **覆盖任何既有美术前一定先备份**，并在汇报里给用户**回退命令**。

## 7. 校验工具箱：AI 看不见图时的眼睛

| 工具 | 命令 | 回答什么问题 |
|---|---|---|
| `ascii_alpha` | `--preview` | 剪影成立吗？有破洞/悬空/断裂吗？ |
| `ascii_class` | `--preview` | 每个部位是什么颜色？色块分布对不对？ |
| `scan` | `--preview --no-fit --scan 88` | **排版错位的唯一可靠检查**：某 y 上从左到右分别是什么 |
| `small_view` | `--preview --small 40` | **40px 真实显示下还认得出吗** |
| `stats` | `--stats` | 亮度/纯度/亮暗占比，可跨版本比较 |
| `make_sheet` | `--sheet` | 出给**人**看的验收图（贴纸色底 + 多尺寸） |

读法示例（真实输出，y=88 一层）：

```
y= 88 | 38-39:# 40-44:R 46-54:Y 59-69:Y 73-80:Y 84-87:R 88-89:#
                墙线   左柱   左窗    中门    右窗    右柱   墙线
```

一眼就能确认"门在正中、窗分两侧、柱在最外"，不需要看图。

**两个关键技巧**：

1. **用 `--no-fit` 做扫描**。`fit_icon()` 会把内容裁边缩放，坐标全漂 → 扫描值对不上设计值。
   `--no-fit` 保留原始排版坐标，扫描才有意义。
2. **色表字母要挑距离远的颜色**。`ascii_class` 取最近色，
   我把 `GLOW` 和 `STONE` 放太近时，边缘混合色会误判，读图白费力气。
   ⚠️ **绝对不要用缩放平均**（`Image.BOX`）再判色 —— 平均会把墨线和亮面混成中间色，整图误报成一片泥。

## 8. 坑位清单（全部实际踩过，附根因）

### 8.1 PIL 的描边方向（**最容易废图的一条**）

| 调用 | 描边画在 | 后果 |
|---|---|---|
| `d.rectangle(outline=…, width=…)` | **矩形内部** | 4px 宽的朱红柱 + 1.4px 描边 → 朱红只剩 1px，**柱子根本红不起来** |
| `d.rounded_rectangle(…)` | 内部 | 同上（大形状才吃得消） |
| `d.line(…, width=…)` | **居中**（向外扩 width/2） | ✅ 正确选择 |
| `d.polygon()` | 不描边 | 必须自己 `d.line(p+[p[0]])` |

**结论**：`kit.rect()` 已强制走「填充 + 居中描边」。自己写新构件时别再直接调 `d.rectangle`。

### 8.2 小形状被描边吃掉

5×5 的三角形 + 2px 居中描边 → 只剩 1.6×2 的彩色核心，看起来是一坨黑。
**规则**：构件 <6px 时，描边 ≤1.0；**纯剪影类附件（鸱尾、幡）直接 `outline=None` + `fill=INK`**。

### 8.3 颜色撞车

- `GLOW_HOT (255,242,202)` vs `WALL (245,236,219)`：距离 20 → **门和墙同色，门等于没发光**。
- `ROSE (176,128,122)` vs `STONE (144,134,118)`：亮度差仅 7 → **纱帘糊进墙里**。
- 对策：改完任何主色，**重跑 §4.2 的亮度/距离表**，别凭感觉。

### 8.4 影子的位置

`ground_shadow(box=(30,104,98,114))` 会**被台基(y102~110)+keyline(到 111.4) 完全压住**，
最终只剩 1px、alpha 32 的余晖 —— 等于白画。
**要影子就把 box 放在台基下缘之外**（如 `y=110~120`）。
> 现状：`qinglou` 的影子就是无效的（不影响观感，但别再抄这个数值）。

> 另一件怪事：改了影子色常量后，输出**只差 464 个 alpha=3~4 的边缘像素 ±1**。
> 这属正常（低 alpha 混合时颜色只贡献零点几），**别当成 bug 去查**。
> 但反过来说：**渲染是全确定性的**（同代码多次渲染 md5 相同），
> 所以“md5 变了”就是真变了——要么代码变了，要么文件被外部进程动了（见 §8.7 OneDrive）。

### 8.5 悬空与漏缝

- **灯笼吊绳**要接到檐角高度（青楼用 `hang_y=66`，正是腰檐角部），否则灯笼浮在空中。
- **两层墙之间**别留缝：腰檐必须压住下层墙顶（青楼一层墙顶 72，腰檐中段 74~78）。

### 8.6 排版重叠：先算"开间"

画窗/柱前先把墙宽减柱子宽，分成几个 bay，再在 bay 里放窗。
青楼二层：墙 `46~82`，柱 `46~50 / 62~66 / 78~82` → 可用 bay `50~62` 与 `66~78` → 窗放 `51~61 / 67~77`。
**先摆柱再摆窗**；反过来一定重叠（我第一版窗 `48~60` 就压住了 `46~50` 的柱子）。

### 8.7 工程/环境坑（Windows + bash）

| 坑 | 现象 | 对策 |
|---|---|---|
| 覆盖同名 PNG | `OSError: [Errno 22] Invalid argument`，**偶发**，与相对/绝对路径无关 | `kit._safe_save()`：写 `.tmp` → `os.replace` + 重试；**PIL 必须 `format="PNG"`**（`.tmp` 后缀会 `unknown file extension`） |
| **OneDrive / 杀软同步** | ① 锁文件 → 上面的 EINVAL；② **已落盘的图被静默回滚成旧版本**（实测撞到：磁盘资产比代码旧一个版本，而 mtime 反而更新） | 落盘后**必须**跑 `python selftest.py`（含"资产 vs 代码逐字节一致"检查）；桌面目录尽量别放源文件 |
| bash `cmd \| iconv \|\| cmd` | 兜底重跑导致**脚本执行两次** → 第二次把"新图"当旧图备份，**原始美术被覆盖** | 别用 `\|\|` 兜底重跑；**项目在 git 里，`git show HEAD:<path>` 可完整还原** |
| `mv _backup/*.png 目标名` | 通配符同时匹配多个旧备份 → 多源单目标 → **mv 整体失败（静默，若加了 `2>/dev/null`）** | 精确文件名，别用宽通配符 |
| 控制台 GBK | `print("⚠ …")` → `UnicodeEncodeError: 'gbk' codec` | 脚本内打印**只用 GBK 安全字符**（本项目中文本身没问题，别用 ⚠ ✅ 等符号） |
| 备份覆盖备份 | `--backup` 固定文件名 → 反复调参时互相覆盖 | 已改**时间戳命名** |
| **`with_palette` 只改一个模块** | 日图的**屋顶仍是夜色**（主色还是夜 TILE），但窗/墙变了 —— 半生效最难查 | 构件函数（`roof/eave/lantern/figure/drum`）在 `kit` 里读 kit 的全局，render 函数在 `buildings` 里读 buildings 的全局 → **两个模块都要改**。已内建 |
| **想给散笔线稿“自动上色”** | floodfill 从四角一灌到底，`inn` 只填出 52px（`academy` 这类闭合的才有 3912px） | **用户的线稿是散笔不是闭合轮廓**（屋顶线 + 柱 + 底座，处处开口）→ 放弃自动填色，改成「线条反白 + 背光」，对任何线稿都稳 |
| **vite 图标强缓存** | 换了图但地图上还是旧图 | `/mapicons/*` 被设为 `immutable, max-age=1y` → 需硬刷新 |

### 8.8 备份与还原

- 覆盖既有美术前：`--backup`（写进 `icongen/_backup/`，带时间戳）。
- 用户资产在 git 里：`git show HEAD:trpg-client/public/mapicons/<key>.png > 还原路径`。
- **备份目录别放 `public/`**（会被 vite 当静态资源、也可能污染 manifest）。

## 10. 模板：抄这个画新建筑

下面这份是 **单层店铺/民居**（最常见的一类），已实测可运行。
关键：**单檐建筑不要让屋顶和墙之间留缝** —— 檐口中点要比墙顶低，压在墙上。

```python
# buildings.py
def render_mymidbuilding():
    """一句话说明这个建筑 + 识别要点。"""
    body, d = blank()
    shadow = ground_shadow(box=(30, 112, 98, 122))     # ⚠️ 放台基下缘之外才看得见，见 §8.4
    cx, wall_top, ground = 64.0, 76, 104

    # 1) 台基
    poly(d, [(34, ground), (94, ground), (98, ground + 8), (30, ground + 8)],
         fill=STONE_DK, width=1.4)

    # 2) 墙身 + 墙脚水渍（脏感来源）
    rect(d, 42, wall_top, 86, ground, fill=STONE, width=1.4)
    band(d, 42, ground - 6, 86, ground)

    # 3) 先摆柱（定出开间 bay），再在 bay 里放门窗 → 不会重叠
    for x0, x1 in ((42, 46), (82, 86)):
        rect(d, x0, wall_top, x1, ground, fill=VERM, width=1.1)
    window_glow(d, 50, 84, 62, 96, mullions=1, width=1.1)        # 灯火窗
    rect(d, 66, 86, 78, ground, fill=GLOW, width=1.3, radius=5.0)   # 券门

    # 4) 单檐：檐口 78 > 墙顶 76 → 屋顶压住墙，不会漏出透明缝
    roof(d, cx, 34, 8, 44, 78, 66, chiwei=True)

    # 5) 点景（吊绳接在檐角高度 72）
    lantern(d, 38, 72, body_top=78)
    lantern(d, 90, 72, body_top=78)

    return compose(shadow, body)


BUILDINGS = {
    "qinglou": render_qinglou,
    "mymidbuilding": render_mymidbuilding,   # ← 别忘了登记
}
```

> **要画重楼/重檐**（楼阁、城门楼）：在上面的基础上加一层墙 —— 即
> `屋顶(上层) + 上层墙 + 腰檐 + 下层墙`，相邻两层必须重叠 2px 以上，否则中间会漏缝。

## 11. 下一步建议：`ward`（坊 / 牌坊）—— 当前唯一缺口

`ward` 是**坊**（里坊/街坊），165 处，量最大。**别画成房子** —— 建议画 **牌坊（牌楼）**：
它在南宋是街区入口的标志物，剪影独特、和"房子们"不混，是格子地图上最好的"坊"符号。

```python
# buildings.py
def render_ward():
    """坊 —— 牌坊（四柱三间），街区入口标志。

    形制要点：主楼最高居中，两次间矮且外挑，三者高度必须拉开
    （主楼檐口 42 / 次间脊 48）→ 中间露出柱身，三间才不糊成一坨（第一版就糊了）。
    本骨架已实测可运行。
    """
    body, d = blank()
    shadow = ground_shadow(box=(24, 112, 104, 120))
    cx, ground = 64.0, 110

    # 四柱：内柱（52/76）高到主楼檐下，外柱（30/98）矮到次间檐下
    for x in (30, 52, 76, 98):
        top = 40 if x in (52, 76) else 62
        rect(d, x - 3, top, x + 3, ground, fill=VERM, width=1.2)

    roof(d, cx, 26, 6, 24, 42, 34, ribs=(0.45,), chiwei=False)                # 主楼
    roof(d, 40, 16, 4, 48, 64, 56, ribs=(), ridge_bar=False, chiwei=False)    # 左次间
    roof(d, 88, 16, 4, 48, 64, 56, ribs=(), ridge_bar=False, chiwei=False)    # 右次间

    rect(d, 54, 52, 74, 60, fill=VERM, width=1.1)                             # 正间匾额
    for x in (30, 52, 76, 98):                                                # 夹杆石
        rect(d, x - 5, ground - 6, x + 5, ground, fill=STONE_DK, width=1.0)

    return compose(shadow, body)
```

跑起来后按 §6 走一遍：`--preview --small 40`（40px 下能否看出"门形"）、
`--scan 60,90`（四柱 x 位置）、`--stats`、`--sheet` 交给用户定。
