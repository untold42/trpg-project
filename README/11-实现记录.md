### 16.10 人物表情改由小模型填充（2026-09-17）

- 动因：`特定人物.md` 原本让大模型命中名单→调 `check_expression`→自己填 `expression`，
  相当于每轮往 prompt 里塞 52 人名单，还多一次远程工具往返；而表情本质是 UI 决策（画哪张立绘），
  与 bg/music 同类，候选封闭枚举——正属于小模型。
- 验证：`verify_expression.py`（一次性脚本）：17 条用例，单条 16/17（94%）可接受、0 越界、
  热调用 ~0.25s；批量 13 人 12/13、2.36s。结论：可行。
- 落地：新增 `tools/小模型/expression_sim.fill(events)`（代码查白名单 + 整轮上下文 + 每行一个 enum + 降级）；
  `engine._run` 在 `_finalize` 后、返回事件流前调用（只改返回事件流，不改 `raw`）。
- 契约变更：`总览.md` 删除 `expression` 输出（大模型不再管）；前端 `gametype.ts` 改为
  `expression?: string`（引擎填充，缺失时 `Character.tsx` 回退 `正常.png`或不画）。
- 停用：`check_expression` 进 `registry._DISABLED`（代码保留）；删除 `trpg-world/主持人/特定人物.md`
  （名字表 = `CHARACTER_EXPRESSIONS.keys()`，单一真相源在美术资源）。

### 16.11 NPC 唯一姓名（2026-09-17）

- 策略：每个有实质互动的 NPC 都有独一无二的正式姓名（姓＋名 / 名号），不用职业/身份代称做名字。
- 运行时（`总览.md` 规则 16）：新 NPC 首次出现就当场起名，`speaker` 用姓名（不写进这套机制则只在存档时才改名，运行时仍是「掌柜」）。
- 存档（`存档流程.md` §三 + `save_pipeline`）：`unnamed_characters()` 列出「本局出现、尚无档案」的人
  （不再要求两局都出现），让 LLM 用正式姓名建档；只有代称的另起姓名并把「原称谓」写入 `static`。
- 为什么：姓名是跨系统主键（`get_character` / 档案文件名 / `char_memory.owner` / `world_sim` 人物线程 /
  `expression_sim` 白名单）；代称（「掌柜」）会重名串档、查找出错。
- 遗留：既有用代称的档案/数据（如「元熙布行掌柜」「怀茂青楼老妇」）尚未迁移（见 `TODO.md`）。

### 16.13 宏观时间线扩写 + 叙事字段注入（2026-09-17）

- 背景：原每条只有一句 `text`，GM 拿到“金军犯淮西”这类干巴巴的一句，只能自己现编影响/反应。
- 扩写：89 条统一加 4 个字段——`辐射范围`（地理/社会波及）、`具体影响`（物价/民生/交通）、
  `江湖反应`（门派/帮会/镖行反应）、`GM叙事参考`（可直接用的场景桥段）；保留 `text` 作标题。
- 数据流：`world_sim._content()` 抽取四字段；`ensure_timeline` 增量补充（旧存档也能吃上，不动已触发）、
  `_trigger_macro`/`fast_forward` 写进 `宏观`；`context_view` 的 `预兆`/`宏观` 均带上字段（并去除内部 `已触发`）。
- 效果：预兆不再是光杆标题，GM 能据此提前铺垫（辐射范围/江湖反应），到点触发后又有完整的“具体影响 + 叙事参考”。

### 16.14 宏观时间线去重 + 世界状态 → 世界线程（2026-09-17）

- 动因：原设计把剧本拷进档、再记 `已触发`，但 `_trigger_macro` 无任何副作用、`run_day` 返回值被丢弃——
  「已发生」本可由 `date ≤ 今天` 直接推导。拷贝既冗余、又违背「单一真相源」（改剧本还得增量合并）。
- 改：
  - 新增 `tools/核心/macro_timeline.py`：只读剧本 + `view(今天)` 切窗口，不落档、不记标记；
  - `tools/world_state.py` → `tools/核心/world_threads.py`：只管 NPC 线程（`模拟游标` + `人物线程`）；
    `context_view()` → `threads_view()`（不注入游标）；删 `ensure_timeline` / `_trigger_macro`（`fast_forward` 只推游标）；
  - `游戏数据/世界状态.json` → `游戏数据/世界线程.json`（结构：`{模拟游标, 人物线程}`）；
  - `engine.state_dict()`：注入 `世界线程`（裁）+ `宏观时间线`（现切）。
- 效果：档变小（无 89 条拷贝）；改剧本对所有存档立即生效；「放弃本轮」回滚宏观视图随时钟自动回退，无需标记。
- 用户拍板的数据链路（冻结，勿回退）：
  > 「宏观事件：每跨一天，后端直接读 `宏观时间线.json`，按时间窗口取事件；
  > `世界状态.json` 改为 `世界线程.json`，只存小模型的 NPC 线程，每轮发给大模型。
  > 不需要单独一个文件去记录时间窗口。」

  ⚠️ 禁止再往档里加 `定时线` / `宏观` / `已触发` 之类的副本或进度标记：
  「已发生」= `date ≤ 今天`（推导即可）；「回滚进度」= 时钟回退（自动）。
  以后若要记录世界自行产生的大事（非剧本里的），另开一个独立字段（如 `世界线程.世界大事`），
  不要把只读剧本重新拷贝进档。

### 16.25 画作系统 + 后端主动推送（server→GM push）（2026-09-26 深夜）

**新范式**：以往所有回合由玩家输入触发；本轮起，**后端可在异步任务完成时主动发起一个 GM 回合**。
- `engine.TurnRunner.run_push(event_text)`：**无工具**（`_allowed=set()`）、**不推时间**、`mode="push"`、不覆盖 `_last_turn`；与玩家回合共用 `RLock` 自动排队。`session.push_mode` 让 `build_messages` **跳过「世界变动 / 作画中」注入**（否则会提前消费）。
- 投递：`tools/核心/push.py` 队列 → 前端轮询 `GET /pending`（3s）→ 按与 `/action` 同一套渲染。暂用轮询，未上 SSE。

**画作子系统**（`tools/核心/art.py` + `配置/画作.json`）：
- GM 工具 `commission_painting(作者,题,画面,寓意?,风格?)`：立即返回「作画中」+ `kind:"art"` 事件；后台线程调 **gpt-image-2.5** 生成 → 存 `trpg-server/画作/<id>.png`；完成后 `run_push` 呈现。
- **图不可控 → 语义层为真**：画作的客观内容（`画面`）与可选 `寓意` 由代码存死；GM 呈现时**只描当下这一刻、不替玩家解读**。**不做「解读」功能**——玩家自己读。
- **寓意可空**：作画未必有言外之意（可能只是享受艺术），schema 与注入都不逼 GM 硬编含义。
- **画作台账常驻 GM 上下文**（`art.context_view()`：作者/题/画面/寓意/状态/时间，含作画中与已完成；**仅 GM 可见**）。作画中也在内 → 玩家中途问，GM 答「还在画」。

### 16.26 双GM 拆分（叙事GM / 工具GM）+ 异步工具日志（2026-09-26 夜）

> 设计文档：`trpg-server/文档/设计-双GM拆分.md`。开关 `配置/双GM.json`（**默认关**）。

**动机**：一个 GM（DeepSeek）既叙事又扛 24 个工具 schema、还要跑工具循环 → 分心、占 token。

**最终方案（叙事即意图）**：
- **叙事GM**（DeepSeek，**只 4 个只读工具**：`query_nearby` `get_character` `get_ability` `DB_query_tool`）：只出 narration/chat，**不写工具意图**、不碰状态。
- **工具GM**（luna，**17 个写工具**）：**读整段叙事**，自己判断该改哪些状态、调工具落地。**异步**（单 worker + FIFO）。
- 链路：DS 叙事立即返回 → 工具GM 后台落地 → 写 `sessions/工具日志.jsonl` → 推 `kind:"toollog"` → 前端右栏「执行日志」刷新 + 刷新钱/背包。

**纪律 / 关键点**：
- 工具GM **只调「改状态」工具**：`get_state`/`get_money`/`get_inventory`/`query_place`/`list_map_kinds` 等**两边都不给**（给了它会没活干时乱调）；只处理**明确发生**的事、闲聊不调、时间只在叙事写明时动。
- **未落地叙事注入**：后台在跑的叙事每轮注入 DS（「按已发生处理、不要重复」）→ 防连点两轮重复扣钱。
- **旧权威门禁在双GM下跳过**（叙事GM 没有 `update_location`/时间工具，旧门禁每轮白跑一次 DeepSeek）。
- **放弃/回滚**：`GameSession._clear_async_queues()` 在回滚**之前**停掉 `world_worker` / `tool_gm` / `push` / `quest_sim`（治「放弃本轮没清工具GM队列」）。
- **前端**：`ToolLogPanel`（任务追踪条下面，**默认折叠**、点开才看、**只显示有实际调用的轮次**、内部可滚）。
- **`run_push`（server→GM push）**：后端可在异步任务完成时**主动发起一个 GM 回合**（无工具/不推时间/`mode="push"`），画作呈现走它；结果进 `push` 队列由前端轮询 `GET /pending`。

**实测结论（别忘）**：DeepSeek **关思考会漏写意图、甚至整轮空输出** → **必须开思考**；「用自然语言描述该改什么」比「函数调用」更依赖思考。叙事GM 工具砍到 4 个 + 注入「附近实名地点」后，工具轮数 **2~4 → 1 轮**。
