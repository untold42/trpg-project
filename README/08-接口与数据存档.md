## 十一、接口：路由 / 工具 / 事件信封

### 11.1 路由

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/location` | 玩家坐标 |
| GET | `/explored` | 玩家坐标 + 足迹 + 解锁半径（顺带记足迹） |
| GET | `/state` | 玩家真实状态（金钱/状态/背包/属性/基本信息） |
| GET | `/factions` | 玩家可见势力条目（画廊用，源 `trpg-world/势力介绍.json`） |
| GET/POST | `/settings` | 游戏设置（难度；源 `游戏数据/难度设置.json`） |
| GET | `/recap` | 前情回顾（≤10 段 narration + 最后一幕 bg/音乐） |
| GET | `/history` | 本局历史 `{active, lines, tail}`（面板 + 续玩） |
| GET | `/clock` | 连续时钟锚点（前端本地插值；顺带 `time_flow.pump()`） |
| POST | `/clock/pause` · `/clock/resume` | 前端暂停 / 恢复时钟（菜单、历史面板、窗口失焦） |
| POST | `/action` | 游戏主循环 `{input, mode, ke?, 坐标?, 上一坐标?}` → 事件流 |
| POST | `/explore` | 玩家自主切回探索（纯前后端，不经 GM）→ `mode:explore` + 通用 BGM |
| GET | `/facility` | 设施「详细」选项 + 背景 `?kind=&name=`（不调模型、秒回；背景查映射表） |
| GET | `/skilltree` | 技能树全貌 + 状态（技能点 / 每节点已学·可学·锁定；不调模型、秒回） |
| POST | `/skilltree/learn` | 点亮技能 `{name}`（花技能点 → 写 `属性.json` + `招式表.json`） |
| POST | `/run` | 探索奔跑结算 `{奔跑米}` → 按超出步行的距离扣精力（返回最新状态） |
| GET/POST | `/recall` | 地点「回忆」（点 POI；只查 `gm_memory` RAG） |
| POST | `/save` | 存档收尾管线（蒸馏→誊写→归档→重置；亦支持 GET 便于诊断） |
| POST | `/abandon` | 放弃本轮（回滚玩家状态 + 世界线程） |
| GET | `/battle/state` | 当前战斗状态（无战斗 `{active:false}`） |
| POST | `/battle/action` | 战斗提交一个动作 `{动作,目标,招式,目标格,思路}` |
| GET/POST | `/battle/settings` | 思路判定模型（小/大模型） |
| GET | `/battle/roster` | 模拟战斗可选名单（55 人，来自 `武力排名.md`） |
| POST | `/battle/sim` | 模拟开局 `{友方,敌人}`（不回写存档） |
| POST | `/battle/abort` | 中止当前战斗 |

### 11.2 工具清单

- 金钱/背包：`modify_money` `get_money` `modify_item` `add_item` `remove_item` `get_inventory`
- 状态/属性：`modify_hunger` `modify_health` `modify_hp` `modify_tp` `get_state` `get_ability`
- 养成 / 设施：`use_facility`（设施活动结算：点数 / buff）；管道 `tools/核心/growth.py`，数值 `成长.json`
- 移动/时间/天气：`update_location` `advance_time`（推进 N 刻/时辰） `update_time`（直接设置） `sleep` `update_weather`（天气由系统自动给，无查询工具）
- 模式：已退役 `resume_exploration`——叙事→探索改为「探索」按钮确定性切换（`_DISABLED`，`TRPG_RESUME_TOOL=1` 可回滚）。
- 骰子：`roll_dice`（可能性骰；日常/旅途骰子已停用，见 §17 与 `TODO.md`）
- 战斗：`start_battle`
- 记忆库：`DB_query_tool` `DB_add_and_update_tool` `DB_query_tool_in_saving`
- 地图查询：`query_nearby` `query_place` `list_map_kinds`
- 人物/表情：`get_character`（表情由 `expression_sim` 小模型填充；`check_expression` 已删）
- 文件（默认禁用，不下发/不可调用；`TRPG_FILE_TOOLS=1` 可启用）：`list_directory` `read_file` `write_file` `edit_file`

> 注册表 `tools/大模型/registry.py` 的 `_ENTRIES` 是单一真相源：
> - `ALL_TOOLS`＝游戏中可用（排除存档专用 + 禁用）——当前 24 个（排除了 5 个存档专用 + 7 个禁用：4 文件工具 + 2 内容生成型骰子 + `resume_exploration`）；
> - `SAVE_TOOLS`＝存档蒸馏白名单（只发这些，防 prompt 撑大/超时）：
>   `DB_add_and_update_tool` `DB_query_tool` `DB_query_tool_in_saving`
>   `update_character_archive` `update_place_note` `update_place_structure`
>   `get_character` `query_place` `query_nearby`；
> - `_ENTRIES` 当前 36 条（含 4 个禁用文件工具 + 2 个已停用骰子 + 5 个存档专用；`check_expression` 已删）；
> - 存档专用（游戏中 GM 不可见）：`update_character_archive`（角色档案）、`update_place_note`（地点见闻）、`update_place_structure`（建筑内部结构）。

### 12.1 数据结构

```
trpg-server/配置/时间影响.json            ← 时间流逝的数值参数（热改免重启）
trpg-server/配置/移动.json                ← 探索移动参数（基础步速 / 轻功系数 / 奔跑倍率 / 奔跑耗精力）
trpg-server/配置/战斗数值.json            ← 战斗全局数值（命中 / 梯度 / Buff / 武器 / 战术 AI 等）
trpg-server/配置/天气.json                ← 天气分区 / 极端权重 / 结构化规则影响（热读）
    每时辰精力{昼,夜} / 睡眠回满时辰 / 夜时辰
trpg-server/游戏数据/              ← 与 tools/ 同级
    基本信息.json   人物 / 时间(日期·时辰·刻·纪年·干支) / 位置(经纬度·区域·在城内/距城墙/最近城门/城区方位) / 天气(状况·温度·风力·描述·结构化影响·影响文本)
    时钟.json       连续时钟真相源（`{游戏秒, 状态}`）——不进 LLM 上下文
    状态.json       生命 / 精力 / 饥饿(0~100 数值 + `饥饿挡位`) / 伤势 / 健康（上限由 `属性` 派生；饥饿消耗读取 `时间影响.json`，当前每时辰 -5；挡位阈值 80/60/40/20）
    背包.json       物品
    属性.json       基础属性 + 五行（只读 `get_ability`；养成写入接口待做，见 TODO §六）
    金钱.json       金钱（+ `最近支出`：最近 3 笔扣费账本，为“同一笔只扣一次”兼底）
    难度设置.json   难度（轻松/普通/困难/硬核）——随状态现拼每轮发给 LLM
    足迹.json       探索足迹（不进 LLM）
    游戏存档.md     上一局逐字叙事（开局读作前情；存档时由代码覆盖）
    世界线程.json   小模型 NPC 推演线程（游标 + 人物线程）—— 首次推演时生成
                    （宏观时间线不落档：只读剧本按当前日期现切，见下）
    导演简报.json   导演（GLM）每局一次产出的幕后简报（常驻注入；空则不注入）
trpg-server/天气数据/              ← weather_system 读取（4 区、每区 366 天）
    东部城市.json / 北部城市.json / 南部城市.json / 西部城市.json
trpg-server/归档存档/              ← 存档时归档的逐字叙事: `<起>~<止> 存档.md`
trpg-server/sessions/           （.gitignore）
    current.jsonl         本局过程日志（每轮一行）
    run_start_state.json  本局开局快照（放弃本轮回滚用）
    battle_settings.json  战斗设置（思路判定模型）
    audit.log             存档蒸馏审计日志
```

### 12.2 地点知识与建筑结构

| 内容 | 存储 | 写入者 | 说明 |
|---|---|---|---|
| 静态说明 | `features.description`（空间库） | 建库时 | 可为空 |
| 动态见闻 `place_notes` | 独立表（建库不删） | 存档专用 `update_place_note` | 「某地发生过的事」，多条 |
| 建筑内部结构 `place_structures` | 独立表（建库不删） | 存档专用 `update_place_structure` | 几层/格局/谁住哪/门通向哪；一旦写入永久有效 |

- `query_nearby` / `query_place` 命中地名时合并返回 `description` + `notes` + `结构`；`map_query._ensure_place_schema` 懒迁移旧库。
- 存档附加任务（代码统计）：① 本局进去过的建筑（`update_location.place_name` 剔除非建筑）→ 让 LLM 用 `update_place_structure` 确定内部结构；② 本局出现、还没档案的人（本局 `chat` 说话者）→ 让 LLM 用正式姓名建档（若只有职业代称则另起姓名，`static` 记「原称谓」）。
- 点 POI「回忆」只走 RAG：`/recall` 只返回 `gm_memory` 语义检索 Top2，不返回见闻/建筑信息（那些是 `query_place` 的事）。
