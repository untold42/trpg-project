### 13.3 地图

数据流（v4 · 多城市，已稳定，勿手改中间产物）：

```
trpg-map/数据/源pbf/<城市>.pbf            （原始 OSM；岳阳用 湖南.pbf 全量，才能拿到完整洞庭湖）
   │  pbf_to_json.py --city <城市>         按「城市画框」裁切
   ▼
trpg-map/数据/<城市>_OSM精简.json         勿改
   │  draw_tiles/build_world.py           保留自然地理 + 算法生成城区 + 建筑群
   │     （读 <城市>_布点锚点.json / <城市>_建筑群.json / <城市>_POI.json）
   ▼
trpg-map/数据/<城市>_南宋世界.json        勿手改
   ├─ export_clickable.py   ► public/data/<map_id>/clickable.geojson
   ├─ db/create_spatial_db.py ► db/map_spatial_<map_id>.db
   ├─ export_walkable.py    ► public/data/<map_id>/walkable.geojson（碰撞 + 地形）
   └─ tilegen/generate_tiles.py ► draw_tiles/tiles/<map_id>/ (z11–16)
                                  └─ 生成.py sync ► public/tiles/<map_id>/
```

- 瓦片 `trpg-client/public/tiles/<map_id>/{z}/{x}/{y}.png`（无 z17/z18，z18 下放大 z16 4 倍）
- 点击层 `public/data/<map_id>/clickable.geojson`；碰撞/地形层 `public/data/<map_id>/walkable.geojson`
- 图标 `public/mapicons/<键>/{day,night}.png`（全局共用，不分城市）
- 民居默认**不生成**（定位单位是「坊」，不需要具体房屋；`TRPG_HOUSES=1` 回滚）；城门=主街穿墙处。
- 一键：`python 生成.py --city <城市>`（见 §三）。详细生成说明见 `trpg-map/draw_tiles/STATUS.md` 与 `trpg-map/数据/README.md`。

**城池尺寸（方形分档）**：`trpg-map/城市.py` 的 `CITY_SIZES` = `10/20/30/40/50` km²（5 档，皆方形）。城市在 `build_world.py` 的 `CITY_CONFIGS` 写 `"尺寸"` + `"城池中心"`，`old_city_bbox` 由 `square_bbox()` **自动派生**（显式 `old_city_bbox` 仍可覆盖，兼容旧城）。POI 数量 / 坊 / 城门数 / `_ward_class` 阈值 / 城外采样内径 均按城池大小缩放。

**差异化城市 · 基础设施分配表**：`trpg-map/数据/基础设施分配.json`，分「通用」（每城必有）与「地域」（按城市声明的标签追加）。地域标签：`水乡 / 沿海 / 大湖 / 大河 / 边关 / 山矿 / 纺织 / 蔗糖 / 都会`。城市写 `"地域": [...]`，实际 POI 池 = 通用 ∪ 命中地域。例：`市舶司` 只在「沿海」城出现。改表即时生效（重跑 `build_world`）。
表里还有两个尺寸联动的控制：**`每档总量`** = 全城最终 `custom` POI 目标数（城内+城外；基准 5 km²=1430，逐档 ×1.75 → `[2500,4400,7700,13500,23600]`）；**`限量`** = 每种设施的全城上限（州衙/城隍庙=1，县衙随城大 `[1,2,3,4,5]`，市集 `[4,6,8,10,12]`…）。被限量的种类达上限后从抽样池剔除；布点锚点不受限量管。
> ⚠️ 改城池尺寸后旧 POI 冻结表作废 —— 用 `TRPG_REFREEZE=1 python 生成.py --city <城市>` 重新生成并覆盖冻结表。

### 13.5 多城市（扬州 / 岳阳）

> 核心心智模型（很重要）：
> 玩家坐标决定「游戏城市」；看哪张地图只是前端 UI，零副作用。

#### 两条互不干扰的链路

| | 决定什么 | 判断依据 | 切了会怎样 |
|---|---|---|---|
| 游戏城市（后端） | GM 查地图用哪个空间库；城池内外、附近有什么 | 玩家经纬度落在谁家画框内（`map_settings.get_map()`） | 只有玩家真的动到那座城才会变 |
| 查看地图（前端） | 屏幕上的瓦片 / 点击层 / 碰撞层 | URL `?map=<map_id>`（> localStorage > `yangzhou`） | 纯 UI，不动坐标、不清足迹 |

想真去另一座城 = 让坐标过去（`update_location(那城的坐标)`，如渡船）。
步行/探索模式禁止跨城（硬闸，防前端光标异常把玩家弹到几百公里外）。

#### 资产目录（一城市一套，互不覆盖）

```
trpg-client/public/tiles/<map_id>/         瓦片
trpg-client/public/data/<map_id>/          clickable.geojson / walkable.geojson
trpg-map/draw_tiles/tiles/<map_id>/        瓦片生成暂存
trpg-map/draw_tiles/db/map_spatial_<map_id>.db   空间库
trpg-map/数据/<城市>_*.json                 源与中间产物（中文名，无 map_id）
```

`map_id` 是英文目录名，单一真相源：`trpg-map/城市.py` 的 `CITIES[城市]["map_id"]`
（`扬州`→`yangzhou`，`岳阳`→`yueyang`）。

#### 前端入口

| 文件 | 作用 |
|---|---|
| `src/in-game/mapId.ts` | `MAP_ID`（`?map=` > localStorage > `yangzhou`）、`tileUrlFor(mapId)`、`dataUrlFor(mapId, name)` |
| `src/api.ts` | 后端地址常量（改成单一处） |

### 13.6 地形步速倍率 + 轻功 + 奔跑耗精力

WASD 走路的屏幕速度 = `步速 × 地形倍率 × 时钟倍率`。倍率随脚下地形实时变。

- 步速 = 基础步速 × 轻功系数：`移动.json` 的 `基础步速`（默认 2.2 米/游戏秒）×（`1 + 轻功 × 轻功每点步速`，默认每点 0.005 → 轻功 100 = ×1.5）。参数由 `GET /state` 随状态下发给前端。
- 奔跑（按住 Shift）：速度 × `奔跑倍率`（默认 2.6）。只对「超出步行的那部分距离」按 `奔跑耗精力每米`（默认 0.006）扣精力——前端累加后 POST `/run` 结算（时间流逝已在扣精力，不双重计费）。
- 数据：`export_walkable.py` 的 `TERRAIN_RULES` → `walkable.geojson` 里的 `terrain` 层
  （`properties.mult`）；道路也带 `mult`（`官道 1.15` / `坊巷 1.0`）。
- 规则（优先级：路 > 地形 > 平地）：在路廊道内用路的倍率；否则取覆盖该点的最重一层。

| 地形 | 倍率 | m/游戏秒 | km/游戏时 |
|---|---|---|---|
| 官道 | ×1.15 | 2.53 | 9.1 |
| 坊巷 / 平地 | ×1.00 | 2.20 | 7.9 |
| 园地 | ×0.95 | 2.09 | 7.5 |
| 农田 / 墓地 | ×0.90 | 1.98 | 7.1 |
| 果园 | ×0.75 | 1.65 | 5.9 |
| 草地 / 树列 | ×0.85 | 1.87 | 6.7 |
| 草甸 | ×0.80 | 1.76 | 6.3 |
| 灌木 | ×0.65 | 1.43 | 5.1 |
| 林地 | ×0.60 | 1.32 | 4.8 |
| 滩涂（湿地） | ×0.45 | 0.99 | 3.6 |
| 山地 / 山岩 | ×0.35 | 0.77 | 2.8 |

- 基础步速 `BASE_WALK_MPS = 2.2`（`GameController.tsx`），Shift 跑 ×2.6；时钟倍率默认 10。
- 前端实现在 `walkable.ts` 的 `terrainAt()`；不是平地时右下角显示徽章（`.map-terrain-badge`）。
- 改倍率只需改 `export_walkable.py:TERRAIN_RULES` 再重导 `walkable`（不必重生成瓦片）。

> 因为时钟在探索模式下持续走，走得慢 = 游戏时间也花得多，二者自洽。

### 13.4 地图性能（探索模式卡顿）定案

> 症状：「走过的地方流畅，新走的地方卡」；菜单地图（无 WASD）全渲染也流畅。

逐层关测结论：

| 测试 | 结果 | 结论 |
|---|---|---|
| `?nohit=1`（关命中层） | 不卡 | → HitLayer 是主因 |
| `?noicons=1`（关图标层） | 卡 | 图标层不是主因 |
| `?nopan=1`（关相机） | 稍有掉帧 | 相机次要 |
| `?nofog=1`（全渲染） | 最流畅 | 迷雾让 `data` 频繁变 → HitLayer 重建 |

根因：`HitLayer` 的 effect 依赖 `[map, data, extents]`；迷雾开着时每走一段 `visibleFeatures` 就是新数组 → `data` 变 → 整个 canvas 图层被拆掉重建（新建 `L.canvas()` + `clearLayers()` + `addData()` 几百个 `L.Path`）。

已修：`HitLayer` 重写——图层只挂一次（`useEffect([map])`，`data`/`extents` 走 ref）、`Map<Feature, L.Layer>` 增量增删、renderer 只建一次；`render(mode)`：`viewport` / `data` / `clear`。同时修了「图标缓存键不含 URL → 先画兜底圆点后无法恢复」的 bug。

逐层开关（URL，可叠加，HUD 显示当前关项）：`?noicons=1` `?nohit=1` `?nopan=1` `?nofog=1`。

残余：`?nopan=1` 仍稍有掉帧，疑为瓦片首次加载 / 首次放大合成（假设 A/D），未处理。可选：前端预热（`new Image()` / `img.decode()`）或生成城区 z17/z18（±5km ≈ 45MB）。

调试 HUD（`Map.tsx` 顶部 `DEBUG_HUD`，挂 `document.body`）：FPS / 最差帧 / 图标数 / 命中数 / 可见数 / 两层重绘耗时。

#### 血泪坑（勿重踩）

1. 不要给 Leaflet 的 pane 加 `will-change`——直接黑屏（瓦片放大 4 倍 + 几百 marker 吃满显存）。
2. Hooks 绝不能放在 early return 之后——直接白屏（"Rendered more hooks than during the previous render"）。
3. 改 hook 顺序后必须硬刷新（Ctrl+Shift+R），否则 HMR 失效。
4. 不要每帧 `panBy`（内部会 `fire('moveend')` → Canvas 矢量层全量重绘）；相机用 `map._rawPanBy()`（Leaflet 私有 API，需强转）+ 整数像素。
5. 原地 push 的数组若下游用 `useMemo`，必须有版本号才会重算。
6. 探索模式迷雾不用 `足迹.json`（用户明确要求），用玩家位置单点气泡 `focus`；旧足迹代码路径已不走。
7. 菜单地图（总览图）已改为按「已探索足迹」启用迷雾（`showAllIcons` 已删）——未去过的区域只留地形瓦片，POI 不显示也不可点；看别的地图时同理（没去过就全黑）。调试关迷雾用 `?nofog=1`。
