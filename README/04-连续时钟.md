## 六、连续时钟 v0.2（核心）

#### 动机

把游戏从"聊天框为主 UI"升级为"世界为主 UI"：地图是主界面（WASD 自由走），
按 Enter 才调 LLM 出场景。时间是这一切的骨架——它必须自己流动，而不是靠
`update_time` 一次次离散推进。

#### 6.1 数据模型：一个标量

```
单一真相源 = 一个单调递增的整数标量「游戏秒」（自纪元起）
其余全部派生：日期 / 时辰 / 刻 / 昼夜 / 季节 / 天气
```

为什么不用维护日历对象："过去"不需要时钟 —— `current.jsonl` 每行已带当时时刻。
标量只管"现在"，历史记录里存"那时"。

落点：`trpg-server/游戏数据/时钟.json`：`{ "游戏秒": 1234567, "状态": "running" }`。

投影到 `基本信息.时间`：`{日期, 时辰, 刻, 纪年, 干支}`——`纪年`/`干支` 是给 LLM 看的
（年号由后端裁决，不让模型猜）；`时钟.json` 本身不进 LLM 上下文（裸秒数徒增困惑）。

#### 6.2 状态机

```
RUNNING    探索 / 叙事（非 LLM 请求期）—— 实时流动
PAUSED     菜单 / 历史记录 / 窗口失焦 / LLM 请求窗口内
ACCRUING   战斗 —— 冻结实时流，按回合累积，结束时结算
```

| 模式 | 时钟 | 主交互 | LLM |
|---|---|---|---|
| 探索 | `RUNNING` | WASD / Enter | ✗ |
| 叙事 | `RUNNING`（请求窗口 `PAUSED`） | 行动 / 说话 / 继续 | ✓ |
| 战斗 | `ACCRUING`（回合折算） | 战棋 | 仅思路判定 |
| 菜单 / 历史 / 失焦 | `PAUSED` | 面板 | ✗ |

速率：默认 1 真实分钟 = 10 游戏分钟（2/3 刻），即 1 游戏日 = 144 真实分钟；
`TRPG_CLOCK_RATE` 可调，`TRPG_CLOCK=0` 关闭（对照旧行为）。

| 参考 | 数值 |
|---|---|
| 1 游戏日 | 144 真实分钟（2.4 小时） |
| 白天→黄昏（6 时辰） | ~72 真实分钟 |
| 走完全城（约 2 刻路程） | ~3 真实分钟 |

#### 6.3 两个显示粒度（关键）

| 用途 | 粒度 |
|---|---|
| 存储（真相源） | 秒（整数，避免浮点漂移） |
| 发给 LLM | 刻（粗，防微抖动干扰模型） |
| 前端古钟动画 | 秒（细，钟要"会动"） |

> ⚠️ 发给 LLM 只用刻级。否则每轮时间差几秒，模型会困惑"时间怎么一直在跳"。UI 细、LLM 粗。

#### 6.4 前端插值（别每帧轮询后端）

```json
// 后端给一次锚点
{ "游戏秒": 1234567, "服务端墙钟": 1726900000.0, "状态": "running",
  "倍率": 10, "显示": {...}, "纪年": "嘉定十三年正月十六", "干支": "庚辰年" }

// 前端本地插值（requestAnimationFrame）
当前游戏秒 = 游戏秒 + (Date.now()/1000 - 服务端墙钟) × 倍率   // 仅 RUNNING
```

- 每次 `/action` 响应顺带带一份新锚点重新校准（防漂移）。`PAUSED` 停插值，`RUNNING` 重设锚点。
- 古钟组件只更新一个 CSS 变量，不要每帧 `setState`。
- 实现：惰性求值，不跑后台线程：`running` 时 `now = 锚点秒 + (墙钟 − 锚点墙钟) × 倍率`；其余状态冻结在锚点秒。

#### 6.5 与现有系统的联动

| 系统 | 改动 |
|---|---|
| `advance_time` / `update_time` | 两类时间通道：`advance_time`推进（睡一夜/赶路三天）；`update_time` 直接设到某时刻；环境时间由时钟自动推进 |
| 时间权威护栏 `engine._check_time_authority` | 换语义：叙述有大幅跳时却没调 `advance_time` → 提醒（待做） |
| `weather_system` | ✅ 时钟跨游戏日时自动切当天天气（`time_flow.pump()`） |
| `world_worker` | ✅ 时钟跨日时入队（`MAX_TICKS=10` 兜底挂机跨多日） |
| `精力`（`状态.json`） | ✅ 跨时辰随昼夜流逝（夜时辰熬夜更狠）；工具 `sleep` 推进并恢复 |
| `save_pipeline` | 快照 + 分段誊写使用连续时钟 |
| `GameSession` 快照 / `abandon` | 快照必须含时钟标量 |

时间双通道模型：

```
环境时间（走路 / 说话 / 观察）  ←  时钟自己流
叙事跳时（睡一夜 / 赶路三天）    ←  LLM 调 advance_time
```

#### 6.6 为何"LLM 请求窗口暂停"

`TurnRunner.run` / `run_save` 期间 `clock.pause("turn"/"save")`，返回后恢复。
生成延迟不计入游戏时间——玩家不为模型的慢买单；但窗口之外的叙事/探索时间照流。

#### 6.7 年号 / 干支：收归后端

原则：年号是硬事实（总纲第 5 条），不让模型自己猜（它会说错朝代纪年），也不能前后端各维护一份。

- 唯一真相源：`game_clock.ERAS`（南宋全表 1127 建炎 ~ 1279 祥兴，22 个年号）；`era_name` / `ganzhi_year` / `cn_number` / `cn_day` / `chinese_date` / `render_era`。
- 给 LLM：`_sync_locked` 把 `纪年`（"嘉定十三年正月十六"）与 `干支`（"庚辰年"）写进 `基本信息.时间` → 随「状态现拼」自动注入。
- 给前端：`GET /clock` 锚点含 `纪年` / `干支`；前端不再自备年号表。
- 重叠年（1276 德祐/景炎、1278 景炎/祥兴）：取起始年最新的年号，使每个年号都有「元年」。
- 超出南宋 → `公元1220年`；`recap` 也改用 `render_era`。

#### 6.8 时间流逝的后果（`tools/核心/time_flow.py`）

时钟只管"时间"，`time_flow` 管"后果"：

```
pump()   ← 在 /clock、/state、/action 里调用（前端每 60s 轮询 /clock → 挂机也跨日）
  ├─ 跨时辰 → 精力随昼夜流逝（夜时辰 子/丑/寅 = 熬夜，扣得更狠）
  └─ 跨日   → 切当天天气（weather_system）+ 触发世界推演（world_worker）
rest(时辰)   ← 工具 sleep
  └─ 先 pump 结算清醒时段 → 推进时钟 → 睡眠时段按「恢复」而非「消耗」结算
```

- 跨时辰/跨日检测：`clock.take_crossings()`（全局刻 / 日游标；首次只对齐不结算；时间设回过去则重新对齐；大跨度只结算最近 96 时辰）。
- 数值：`trpg-server/配置/时间影响.json`（改文件即时生效）：`每时辰精力.昼/夜`、`睡眠回满时辰`（每时辰恢复 = 精力上限 ÷ 该值，随养成自动变强）、`夜时辰`。
- 工具 `sleep(时辰)`：睡觉推进时间 + 恢复精力；`say`/`gm` 回合被护栏驳回。
