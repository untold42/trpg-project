# 天气系统（设计文档）

> 天气由后端代码产出，LLM 不参与随机与数值计算。
> 唯一策划配置：`trpg-server/配置/天气.json`（支持热读）。
> 实现：`tools/核心/weather_config.py`、`tools/核心/weather_system.py`、`天气数据/*.json`。

## 一、数据流

```
时钟日期 + 玩家经纬度
   │  weather_system.get_weather()
   ▼
按 天气.json 定分区 → 查 天气数据/<分区>.json
   ▼
按 天气.json.影响 取得结构化规则并生成影响文本
   ▼
写回 游戏数据/基本信息.json.天气
```

- `engine.state_dict()` 每轮调用 `ensure_today()`；跨日时 `time_flow.pump()` 也会更新。
- 日期未变化时仍会同步最新规则，因此修改 `天气.json` 无需重启或跨日。
- 特殊剧情调用 `update_weather` 修改状况时，也会自动重算结构化影响。

## 二、分区

| 分区 | 判据 | 覆盖 |
|---|---|---|
| 北部城市 | 纬度 ≥ 32.8 | 淮河以北 |
| 西部城市 | 经度 < 110.5 | 四川盆地 |
| 东部城市 | 经度 ≥ 118.5 且纬度 < 33 | 江淮及江南沿海 |
| 南部城市 | 兜底 | 荆湖、江南内陆等 |

分区规则、优先级、坐标缺失时的关键词兜底均在 `天气.json` 中配置。

## 三、结构化影响

`基本信息.天气.影响` 不再保存“轻功 +10”一类文本，而是固定结构：

```json
{
  "判定修正": {"轻功": -10},
  "效果倍率": {},
  "效果禁用": ["火系"],
  "禁止行动": [],
  "强制行动": [],
  "建议行动": [],
  "环境标签": ["视野严重受限", "声音传递困难"]
}
```

规则：

- `判定修正`：直接加到 d100；负数代表提高难度。例如 `轻功: -10` 即轻功判定难度 +10。
- `效果倍率`：例如 `火系: 0.5`。
- `效果禁用`：对应效果完全无效。
- `禁止行动`：可供出行、航行等系统直接做硬门禁。
- `强制行动` / `建议行动`：区分必须执行与叙事建议。
- `环境标签`：无明确数值但可供规则和叙事读取的环境事实。

`影响文本` 由代码从上述字段生成，只用于人类和 GM 阅读，不再作为数值来源。

## 四、天气字段示例

```json
"天气": {
  "日期": "1220-01-17",
  "状况": "雪",
  "温度": "寒冷",
  "风力": "大风",
  "描述": "雪落无声",
  "影响": {
    "判定修正": {"轻功": -5},
    "效果倍率": {},
    "效果禁用": [],
    "禁止行动": [],
    "强制行动": [],
    "建议行动": [],
    "环境标签": ["地面痕迹可见", "寒冷相关判定"]
  },
  "影响文本": "轻功判定 +5 难度；地面痕迹可见；寒冷相关判定"
}
```

## 五、极端天气

天气数据命中“极端”时，系统按 `天气.json.极端天气权重` 掷 d100，再从“极端天气详情”读取描述与风力。各分区权重必须合计 100，否则配置校验直接报错。

## 六、特殊改天

仅法术改天或极端剧情需要时使用 `update_weather`。常规天气无需调用工具；修改状况后，工具会自动重算 `影响` 与 `影响文本`。
