# 存档流程（本局结束时的记忆蒸馏）

> **誊写存档、归档、重置本局**都由系统代码完成，你（主持人）**不要写任何文件**。
> 你只做三件事：把**客观事实**写进 `gm_memory`；把**人物的近记忆**写进其**动态档案**；
> 把**某地发生的事**写进该地点的**见闻**。

---

## 一、两个去处（分工）

| 去处 | 内容 | 规则 |
|---|---|---|
| `gm_memory`（主持人·客观） | **这个世界到底发生了什么** | 用 `DB_add_and_update_tool`，**只增（add）**，不改 |
| 角色**动态档案**（人物·主观） | 某人得知 / 认为 / 打算 / 感受到什么 | 用 `update_character_archive`，**按人调用** |
| 地点**见闻**（客观·空间） | **某地实际发生过的事** | 用 `update_place_note`，**按地点调用** |
| 建筑**内部结构**（客观·空间） | **某建筑怎么布局**（几层、谁住哪、门通向哪） | 用 `update_place_structure`，**每个进去过的建筑一次** |

> **不写 `char_memory`**。那层「冷库」由系统在动态档案**溢出时**自动淘汰写入（LRU），
> 不需要你手动写。你只管把「当下」写进动态档案。

**关系的拆法**：客观的结盟、敌对 → `gm_memory`；A 对 B 的好恶、猜忌 → 某个角色的动态档案。

---

## 二、蒸馏步骤

0. **先跳过所有 `梁峰（场外）` 开头的行及其后主持人的回答**：那是玩家与主持人的场外元对话（问规则、问律法、补设定），**不是世界内发生的事**，一律不蒸馏。
1. **逐行阅读**《本局完整记录》，提炼**客观事实** → `gm_memory`（`add`，`content` 形如 `日期,发生了什么`，可带 `kind`，如 `event`）。
2. **逐个点名本局有实质互动的 NPC**（对过话、有交手、被记住的），为**每人调用一次** `update_character_archive`：
   - 系统**先查静态档案**：**已存在**（老角色）→ 只更新他的**动态**档案，静态正典不覆盖；
     **不存在**（新角色）→ 用 `static` 建**静态**档案，并建**动态**档案。
   - `feeling`：重大互动追加一条**情感记忆**——从**她的视角**记感受，具体、身体化，不是评价。
   - `milestone`：重要关系节点（谁做了什么）。
   - `emotion` + `behaviors` + `want` + `volatility`：**当下**的情绪状态（每次存档都要更新）。
   - `known` / `unknown` / `info_attitude`：她此刻**知道什么、不知道什么**。
   - `recent` / `attitude`：最近互动摘要 / 她把梁峰当成什么。
   - **新登场的角色**：一并给 `static` 字段（**姓名**/年纪/外貌/身份/性格/说话方式/身世/关系网…）；**老角色不用给**（给了也会被忽略）。`name` 一律用**正式姓名**（见 §三）——若叙事里只出现过职业/身份代称（如「掌柜」），**另起一个符合南宋的姓名**，并把「原称谓：X」写进 `static`。
   - **没提到某人，就不要为他调用**——不要凭空补写。

3. **盘点本局到过的地点，把「值得记住的事」记成见闻** → `update_place_note(place, note, time)`：
   - `place` 用**地图上的地名全称**（如「怀茂青楼」「太阳坊」）；
   - `note` 一句话，写清楚**时间/人物/事由**（如「梁峰于丙字房强暴陪坐琵琶女阿沅，未报官」）；
   - **只记大事**（冲突、凶案、交易、失火、某人被抓/遇害…）；路过、吃了碗面不记。
   - 以后任何 `query_nearby` / `query_place` 命中该地名，会自动把见闻显示出来。

4. **给本局进去过的建筑确定「内部结构」** → `update_place_structure(place, structure, time)`：
   - 系统会在《附加任务》里列出**玩家本局进入过的建筑**；对**还没有结构**的，调用一次把它定下来
     （几层、前堂/后院、哪间是谁的、门通向哪）。**已有结构、本局没新发现的不用重写**。
   - 写进空间库后**永久有效**——以后 `query_place` / `query_nearby` 都会返回 `结构`，不必再现编。
   - 例：「怀茂青楼：两层木楼。前堂设柜台与旧木楼梯；二楼为客房与姑娘住处，丙字房在二楼廊道尽头，东家老妇住二楼东头。楼后一方小院，有灶房、柴垛、水井与看门耳房，另有侧门通后巷。」

5. **给「还没有正式姓名」的人命名**（见 §三）：系统会在《附加任务》里列出这类人物（本局出现、尚无档案）；
   起一个符合南宋的**姓名（姓＋名）**（江湖人物可用名号），用 `update_character_archive` 的 `static` 建档，
   并在 `static` 里注明其**原称谓**（若此前提及过职业/身份称呼）。

6. **不写 `char_memory`**。若某角色确有一条与旧事直接冲突、需要更正的历史记忆，也**先写进动态档案**，由系统日后淘汰处理。

## 三、人物命名（名字是唯一主键）

- **每个人只有一个名字，且独一无二**。同一人物在所有地方用**同一个规范名**
  （= 静态/动态档案文件名 = `chat` 的 `speaker` = `char_memory.owner` = 世界推演人物线程）。
- **有静态正典档案的**用其全名（如「上官萤」「唐布衣」）；**新登场的角色一律给正式姓名（姓＋名）**，
  符合南宋用字；江湖人物可给**名号**（如「龙王刀」）。
- **禁止把职业 / 身份代称当正式名**：「掌柜」「老妇」「挑炭人」「店小二」「船夫」「妇人」这类
  只能作为**原称谓**记录，**不得当档案名 / `speaker`**。
  - 若叙事里只出现过代称：**另起一个姓名**，用 `update_character_archive(static=…)` 建档，
    并在 `static` 里写「**原称谓：X**」（把旧称呼记进去）。
- **命名尽量在首次登场时当场完成**（运行时主持人直接给名）；存档时系统会列出「本局出现、尚无档案」的人
  作为**兜底**，请补命名。
- **不要与他人重名**；若发现疑似同一人的不同称呼，合并为一个规范名（旧称呼记进「原称谓」）。
- **只出场一次、无互动的背景路人不必建档，也不必起名**。

## 五、铁律

- **只调用工具**，不要输出叙事、不要写文件。
- **`梁峰（场外）` 行及其后主持人的回答都不蒸馏**：那是元对话，不属于世界。
- 客观 → `gm_memory`；人物近记忆 → `update_character_archive`（**不写 `char_memory`**）；地点见闻 → `update_place_note`。
- `gm_memory` 一律 `add`（客观事实不复写）；`add` **不要编 `id`**（系统自动编号）。
- 有实质互动的 NPC **一个都不要漏**；没提到的不要编。
- **每个有实质互动的 NPC 必须有正式姓名**（姓＋名 / 名号）；职业 / 身份代称只能记作「原称谓」，**不得当 `name`**。
- 拿不准时：客观的多写一条，主观的写进动态档案，交给系统淘汰。
