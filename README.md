## 一、核心原则（总纲）

把系统从"一堆脚本各写各的"收敛成**分层的、单一真相源的、事件驱动的**结构：

```
内容层（正典） ──► 引擎层（回合） ──► 表现层（事件流）
        ▲                 │
        │                 ▼
      记忆层（存档蒸馏）  状态层（实时）
```

1. **单一真相源**：每类信息只有一个源，其余都是投影。
2. **类型化接口**：领域数据只能通过专用接口读写，禁止裸文件 I/O。
3. **状态实时、记忆离线**：状态每次现拼；记忆在存档时批量蒸馏。
4. **信息边界（可见性）**：可见性是一等公民。GM 所知 ⊋ 玩家所知 ⊋ 各 NPC 所知；NPC 的言行**只能**基于其知悉集，靠机械隔离而非提示词自觉（见 §5.7）。
5. **硬事实由代码裁决，模型只渲染**：**距离 / 方位 / 城内城外 / 时间 / 数量 / 骰值**等可计算的事实，一律由**代码算出并注入**，**绝不让大模型臆断**——模型只负责"是什么感觉 / 发生什么"，不负责"是多少 / 在哪里 / 何时"。

**"硬事实"清单（均由代码产出，模型只能引用、不得臆断）**：

| 硬事实 | 产出方 |
|---|---|
| 时间（日期 / 时辰 / 刻） | `game_clock` / `time_weather.update_time` |
| 位置、移动距离 / **方位**、耗时提示 | `location.update_location` |
| 城内/城外、**城区方位**、距城墙、最近城门 | `map_query.city_context` |
| 某地相对玩家的**方位 / 距离** | `map_query.query_place` / `query_nearby` |
| 天气 | `weather_system.get_weather` |
| 骰值 / 事件顺利度 | `dice` / `world_sim` |
| 金钱 / 物品 / 生命精力 / 属性 / 饥饿 | 各 `state` 工具 |
| 战斗命中 / 伤害 / HP / 内力 / Buff / 胜负 | `battle` |

> 推论：凡新版规则想写"请主持人估算距离/时间/方位/数量"的，应先问"这一步能不能由代码算？"——能则改代码注入。

## 五、分层详解

### 5.1 状态层 ✅

#### 决策

- **`history` 是真状态**（过程），必须持久化。
- **状态在每次 LLM 调用时现拼，且上下文中只出现一次、永远最新**。
  理由：状态必然影响叙述（"有一万两却不知道"会写偏），但快照会过期，不能塞进 `history`。
- **`history` 只保留纯叙事**（user / assistant 正文），状态与工具中间消息都不进 `history`。
- **`current.jsonl` 每轮追加**：唯一"边玩边做"的更新；一次磁盘 append 成本可忽略，换崩溃安全。
  落盘（每轮，廉价）≠ 蒸馏（存档，昂贵）。
- **`世界线程.json` 放在 `游戏数据/` 下**，因此被"状态现拼"自动纳入每次调用；**宏观时间线不落档**，由只读剧本按日期现切。

#### 机制（已实现）

```python
# 每次调用 LLM 都重新拼装，工具循环里也重拼
messages = [
    {"role": "system", "content": 规则},
    {"role": "system", "content": 前情},        # 上一局存档（若有）
    *history,                                    # 纯叙事
    {"role": "system", "content": 当前状态},      # 现拼，只此一份，放末尾
]
```

- 状态块放 messages **末尾**（稳定前缀利于上下文缓存）。
- 工具循环里**每次 `send_messages` 都重拼状态** → 写最终叙述前看到的一定是刚落地的值。
- 实现：`engine.py` 的 `snapshot_state()` / `GameSession.build_messages()`。
- **上一轮状态 + 当前状态**：`engine.state_stack = deque(maxlen=2)`（只两份、不累积）——每轮末
  `append(本轮状态)`，下一轮把**栈顶**（上一轮）与 `===== 当前状态 =====` 一起发给 LLM；
  探索时时间在流动、玩家在走动，模型自行对比变化，**代码不计算差值**。

#### 边界规则

- `游戏数据/` 是**领域自有存储区**：禁止通用文件工具写（`_guard_game_data()`），只能走专用接口 + `state_manager`。
- **`file_tools` 默认禁用**（`registry._DISABLED`：**不下发给 LLM、也不可被调用**；代码保留在 `tools/file_tools.py`，设 `TRPG_FILE_TOOLS=1` 可临时启用）。LLM 的知识入口只剩：提示注入 + 类型化工具。
- **凡进 `游戏数据/` 的文件，必须有类型化接口**，否则视为设计漏洞。
- **不是所有 `游戏数据/` 文件都进 LLM 上下文**：`snapshot_state()` **排除** `足迹`（探索点）与 `时钟.json`——它们只供前端 `/state`、`/clock` 读；`世界线程` 按「纳入上下文」裁剪后注入，`宏观时间线` 现切窗口注入。
- **并发写保护**：`state_manager` 的 `load`/`save` **同一把 RLock 串行化**、临时文件名带 pid+线程号、`replace` 失败重试；`clock`/`derived`/`time_flow` 写盘失败只记日志；`/state`、`/clock` 副作用 `_best_effort` 永不 500。

#### 派生上限（承总纲第 5 条）

`属性.json` 是真相源——**体力 = 生命值上限，內力 = 精力值上限**；`状态.json` 的
`生命上限`/`精力上限` 只是**投影**。`tools/derived.py` 的 `sync()` 在漂移时以属性为准回写
（上限变小则把当前值夹到上限），由 `engine.snapshot_state()` 与 `time_flow.pump()` 调用
→ **养成提高內力/体力后，上限与睡眠恢复量自动跟上**。

"孤儿"（有文件、无写接口）由代码补接口：`属性.json`（`update_ability`/`train_skill`）、
`混乱度.json`（`evaluate_chaos`）——均未做（见 `TODO.md`）。`游戏存档.md` 已由代码誊写。

### 5.2 记忆层 ✅

#### 两级记忆

```
工作记忆（热）                              长期记忆（冷，chroma）
角色动态档案/活跃/*.md  ──LRU 淘汰条目──►   char_memory（角色/潜意识）
客观事实 ────────────────────────────────►  gm_memory（主持人/客观）
```

- **不对称**：主持人记忆**只增不淘汰**（事实不会遗忘）；角色记忆有容量、会淘汰。
- **淘汰即遗忘，遗忘即潜意识**：角色记忆淘汰后进 chroma，需要时被检索回来，以模糊印象形式回到上下文。

#### 两个 collection（已实现）

```
chroma（trpg-db/chroma_db）  访问层：tools/mem_store.py（懒加载）
├─ gm_memory（主持人）
│    客观事实（世界到底发生了什么）
│    metadata: { time, kind? }
│    写：存档时 LLM 蒸馏，只增
│    读：全局，无过滤
│
└─ char_memory（角色）
     主观记忆（记忆/感情/认知）
     metadata: { owner, time, kind? }
     写：存档时，动态档案 LRU 溢出的条目
     读：局内按需，强制 where owner = 当前视角角色
```

- collection 名必须 ASCII（chroma 限制），故用 `gm_memory` / `char_memory`。
- 工具：`DB_query_tool` / `DB_add_and_update_tool` / `DB_query_tool_in_saving`，均按 `collection` 寻址，角色必带 `owner`。**id 由代码分配**（`_next_id`=max+1），LLM 不编 id。

#### 检索铁律

> 查 `char_memory` **必须带 `owner`**；查 `gm_memory` 才全局。跨 owner 检索视为 bug。

这条同时是**信息边界机制**：`gm_memory` = 客观真相 → GM 主持世界用；
`char_memory[owner]` = 该角色主观认知 → 扮演该角色用；两者之差 = "角色不知道 / 记错了 / 误解了"。

#### 时机

- **局内**：允许只读查 chroma（查询轻）。不写任何记忆。
- **存档时**（`save_pipeline.run_save`）：
  1. LLM 蒸馏本局 → `gm_memory`（客观）+ 角色动态档案（主观，`update_character_archive`）
  2. 角色档案 §10 情感记忆超 20 条 → LRU 淘汰最旧 → `char_memory`（`tools/character_archive.py`）
  3. 代码誊写 `游戏存档.md` + 归档
  4. 重置**会话**（history + current.jsonl）；**玩家状态保留**（故事连续）

> 注：「动态档案 = 存档时快照」已被**世界推演**修订——活跃档案随推演每游戏日更新。

#### 旧格式映射（`存档流程.md` 已照此重写）

| 旧 type | 新归属 |
|---|---|
| `event`（客观事实） | `gm_memory` |
| `information`（谁得知/认为/打算什么） | `char_memory`，`owner` = 那个人 |
| `relationship` | **拆两半**：客观结盟/敌对→`gm_memory`；A 对 B 的好恶→`char_memory[owner=A]` |

#### 关键规则

- **IC / OOC**：`梁峰（场外）` 行是玩家对主持人的元对话，**不蒸馏**。
- **id 命名**：`gm_N` / `char_N`，两库各自计数。

### 5.3 内容层 ✅

- **`trpg-world/` 是正典唯一来源**。对 LLM 只以两种方式进入：提示注入 / 类型化检索。
- **规则层全量注入**：`主持人/*.md`（小、必须每轮在场）。
- **正典层按需检索**：角色静态档案(55)、势力档案、世界设定（大、引用型，全量注入会稀释注意力）——检索接口未做，方案见 §5.8。
- **势力介绍：玩家可见数据独立成文件** `trpg-world/势力介绍.json`（已剔除剧透，人工维护），前端经 `GET /factions`（`tools/factions.py`）读取。**前端不再有 `data/` 文件夹**——所有游戏数据一律向后端请求。

#### 结构（已实现）

3. **状态块位置**：messages **末尾**。

  - `ALL_TOOLS`（游戏中，排除存档专用 + 禁用）
  - `SAVE_TOOLS`（存档蒸馏白名单，见 §十一）
  - `TOOLS_MAP`（`engine.TurnRunner` 用）
- 新增工具只需在 `_ENTRIES` 加一行，不必再改 `llm.py` / `main.py`。

#### 本局生命周期（已实现）

```
本局进行中 ──┬── 存档 POST /save       → 蒸馏 + 誊写/归档 + reset（状态保留）
             ├── 放弃本轮 POST /abandon → 回滚状态到本局开始 + 丢弃日志 + reset
             └── 中途退出/刷新         → 本局保留；GET /history 续玩
```

- **开局快照**：`GameSession` 在本局开始时把 `游戏数据/*.json`（含 `时钟.json`、`世界线程.json`）存到 `sessions/run_start_state.json`；`abandon` 用它回滚。

#### 存档管线（已实现）

```
POST /save
 1. 代码：current.jsonl ──► 逐字叙事 transcript（按游戏内时间分段）
 2. 代码：统计附加任务（本局进过的建筑 / 两局都出现的无名人）→ hints
 3. LLM ：读《存档流程.md》蒸馏 ──► gm_memory / char_memory / 动态档案 / 见闻 / 建筑结构
          （12 轮上限 + 240s 看门狗；失败/超时则跳过，不阻塞机械存档）
 4. 代码：transcript ──► 游戏数据/游戏存档.md（下一局读作前情）
 5. 代码：归档 ──► 归档存档/<起>~<止> 存档.md
 6. 代码：重置会话（玩家状态保留）
```

- 分工：**代码负责机械部分（誊写/归档/重置），LLM 只负责语义蒸馏**。
- 修正了原存档流程的 off-by-one（现在蒸馏并归档的是**本局**）。

### 5.5 表现层 / 事件流 ✅

#### 决策

后端→前端只保留**一条契约**：有序事件流。事件分两类：

| 类别 | 类型 | 前端行为 |
|---|---|---|
| 叙事指令 | `chat` / `narration` | 线性、点击推进 |
| UI 事件 | `type:"ui"`（`kind`: `bg`/`music`/`minigame`/`mode`/`battle` …） | 旁路；`minigame` 可阻塞叙事 |

- **工具副作用**（切背景、放音乐、开小游戏、切模式、开战）通过 **UI 事件旁路**送到前端——解决工具中间消息被清理后副作用传不出去的问题。
- **历史面板 / 续玩**走 `GET /history`（读 `current.jsonl`）；前端不再维护平行的 `historyLog`。
- **元操作走界面按钮**：存档、放弃本轮、地图、势力、返回主菜单均**不由 LLM 工具触发**（确定性 + 二次确认）。
- **模型分工**：大模型只产 `chat`/`narration`；`ui_event` 由**本地小模型**产出。
- 原 `bg` 类型已从 `instruction` 删除。

#### 事件信封（已实现）

工具侧：

```python
from tools.ui_events import ui_event, UI_EVENTS_KEY

def some_tool(...):
    return {"success": True, "message": "...",
            UI_EVENTS_KEY: [ui_event("music", track="市井")]}
```

引擎侧（`engine.TurnRunner`）：取出 `_ui_events` → 收集成流 → **从给 LLM 的结果中剥离** →
返回 `[...UI 事件, ...LLM 叙事指令]`（工具事件在前）。

前端侧：`GameController.sendAction` 拆为叙事（进 `GameScene`）与 UI 事件（走 `handleUiEvents` 旁路）。

#### 输入模式（IC / OOC）（已实现）

`POST /action` 接收 `{input, mode, ke?, 坐标?, 上一坐标?}`：

- `mode:"action"` → 角色行动（IC）。后端组装 `梁峰：<input>` 给大模型。
- `mode:"say"` → **对 NPC 说的话（IC 台词）**。后端组装 `梁峰开口说：「<input>」`，让 NPC 回应，**不作为行动执行**（不得据此跳时间）。
- `mode:"gm"` → 玩家对主持人的场外话（OOC）。后端组装 `玩家的对主持人说的话：<input>`。
- `mode:"continue"` → **「继续」按钮**（可选 `ke` 刻数）：`ke=0` **不推进时间**、只看更多场景信息；`ke>=1` 推进 N 刻。

`mode` 存进 `current.jsonl`。存档誊写时**只改前缀**、不改内容：
IC → `梁峰：…` / `梁峰说：「…」`；OOC → `梁峰（场外）：…`（**禁止蒸馏**）；
旁白 → `GM：…`；NPC 台词 → `GM（人名）：…`。

> 为什么：前缀字符串是脆弱的 UI 约定；"是不是 OOC"必须是**数据**，不能靠猜。
> OOC 是元对话，**不是世界内发生的事**，混进 `gm_memory` 会造假事实。

#### 台词回合时间护栏（规则 12 机械兼底）

`engine.TurnRunner._say_time_guard`：`say`/`gm` 模式下 `update_time` 只允许 ≤ `SAY_MAX_KE=2` 刻的
`advance_ke`，任何推进时辰 / 改日期 / 设时辰都**驳回并回错给 LLM**；`action` 不受限。

#### 界面布局（已实现）

```
左侧 [菜单] ─► 存档游戏 / 放弃本轮 / 地图 / 势力 / 返回主菜单
右侧（竖排）  数据 / 历史记录 / 行动 / 说话 / 继续 / 主持人
```

- 「数据」弹出金钱/背包/属性/状态（读 `/state`）。
- 「菜单」= `StaggeredMenu`（`closeOnContentClick`）。
- 存档/放弃是**界面按钮**；`save_game` 工具已退役。

#### 背景 / 音乐（小模型 UI 事件）✅

- `bg` / `music` 均由 UI 事件控制：`{"type":"ui","kind":"bg","data":{position,time}}`、`{"type":"ui","kind":"music","data":{track}}`。
- 前端：收 `kind:"bg"` → `in-game/background.ts`（地点+时辰→图）；收 `kind:"music"` → `in-game/music.ts`（曲库 = `assets/音乐/*.mp3`，循环播放）。
- **已迁移**：背景/音乐改由**小模型**产出（`tools/ui_sim.py`）：
  - 场景枚举 = 前端 `assets/背景/` 子目录（说明见 `trpg-world/场景清单.md`）；音乐候选 = `音乐清单.md`（叙事）与 `战斗音乐清单.md`（战斗），条目格式 `曲名｜绑定：说明`。小模型只从候选里选（+「无」），无幻觉面。**叙事默认底色曲 = `山中好岁月`**。
  - **背景按地点类型约束**（`ui_sim.scene_candidates`）：查玩家所在地点的 `ancient_kind`，**每类只给 2~4 个候选**（映射见 `场景映射.md`，84 个类型全覆盖）；未映射时用「室内 / 室外」**小兜底组**，防"在城里被切到乡村"。
  - **场景状态机（防抖）**：`engine._scene_ui_events` 只在「强制（探索→叙事）/ 首次 / 地点变化 / 叙事出现进出门·移动」时才允许换背景；`GameSession.last_bg_location` 记录上次换背景时的地点。
  - 叙事选曲（`ui_sim.narrative_tracks`）：**有绑定**的仅当对象在场（命中「地点名 / 地点类型 / 本轮登场人物」任一）才可用，**无绑定**则始终可用；战斗曲在 `战斗音乐清单.md`，叙事候选天然看不到。
  - 引擎做**去重**；换曲规则：背景变化 **或 当前曲已不适用于本地点/在场** 时才允许换曲。

### 5.6 小模型层

本地小模型：**Qwen3-4B**（LM Studio，`qwen/qwen3-4b-2507`）。与大模型**并列**的另一条生成链路。

**统一约束（`tools/small_model.ask_json`）**：

#### 三条管线

| | `ui_event` | 人物表情 | 世界推演 |
|---|---|---|---|
| 时机 | 同步，每轮 | 同步，每轮（有命中才调） | 异步，随游戏日 |
| 延迟敏感 | 高（背景/音乐随场景） | 高（立绘随台词） | 无（off-screen） |
| 输出 | 极小（kind + 字段） | 极小（每行一个枚举） | **两个枚举值** |
| 触发 | 当前叙事 / 场景 | big model 返回的 chat 行 | 推进一个游戏日 |
| 状态 | ✅ 已实现（bg/music） | ✅ 已实现（`expression_sim`） | ✅ 已实现 |

> **人物表情**（`tools/expression_sim.py`）：大模型产 `chat` **不带 expression**；引擎在返回前按
> 「整轮上下文 + 每行的表情枚举」让小模型逐行选表情，就地写回 `event["expression"]`。

> 失败降级（前端回退 `正常.png` 或不画）。实测 0 越界、可接受命中 ~94%、热调用 ~0.22s。
> 详见 §16.10。

#### 世界推演的核心决策（已实现）

> **小模型只做离散采样，具体叙事交给大模型。**

```
每游戏日，对每个活跃人物：
    小模型 ──► { 地点, 事件类型, 纳入上下文 }   ← 都是离散值，幻觉面趋近于零
    代码   ──► 顺利度（加权掷骰，顺+平 ≈ 90%）
        └──► 写入 世界线程.人物线程

玩家遇到该人物时：
    大模型 ──► get_character(name) 读 静态档案 + 动态近记忆
            ──► 自行演绎出既具体、又合正典的叙事
```

**为什么只出极少的离散值**：4B 生成"具体事实"必然与正典冲突，且会被固化成假事实；
抽象成离散状态后它**无从编错**。（实测：不逼它极简时，它会把字段写成整段小说、单次 19s+；严格提示后降到 0.5-2s。）

- **事件类型**（8 选 1）：营生 / 修行 / 社交 / 赶路 / 生活 / 公务 / 寻医 / 变故
- **顺利度**（代码掷骰，5 档）：大顺 5 / 顺 45 / 平 45 / 不顺 4 / 大挫 1
- **地点**：自由文本
- **纳入上下文**（bool）：按**离玩家远近**判断是否进大模型视野；**不改变推演内容，只决定注入裁剪**。

#### 触发与异步（已实现）

```
每次 /action 结束 ──► world_worker.on_turn_end()
    比对「已入队游标」与当前游戏日期
    跨 N 天 ──► 入队 N 个「日任务」（超过 MAX_TICKS=10 则跳过早先的）
                        │  daemon 线程（不阻塞玩家）
                        ▼
   单日：对每个活跃人物采样（是否进上下文由小模型决定）→ 写回世界线程 → 游标推进
         （宏观不在此处理：按当前日期从只读剧本现切窗口）
```

- **入队游标与推演游标分离**：避免"没跑完就被重复入队"；进程重启后自动补缺口。
- **世代号 + `clear(wait)`**：`clear()` 递增世代，队列里/在途的旧任务出队即作废；`abandon` 在**回滚快照前**调 `clear(wait=True)`。
- **写入单一化**：所有 `世界线程.json` 写入只在 daemon 线程发生，消除写竞争。
- **总开关**：`TRPG_WORLD_SIM=0` 关闭。**降级**：小模型调用失败 → 跳过该人物，不写脏数据。
- **不做代码级「在场豁免」**（早期按地点字符串跳过，导致同区域 NPC 线程被永久冻结）——所有活跃人物一律采样，是否进上下文交给小模型。

#### 宏观层（已实现）

- 作者时间线 `trpg-world/世界推演/宏观时间线.json`（**89 条，1220-02 ~ 1279-02，覆盖南宋全程**，参照史实）。
  每条含 **6 字段**：`date` / `text`（一句话标题）/ `辐射范围` / `具体影响` / `江湖反应` / `GM叙事参考`——
  后四个是给主持人的**叙事素材**（地理波及、民生变化、武林反应、可用桥段）。
- **它是唯一真相源：只读、不拷贝、不记「已触发」**。注入时由 `tools/macro_timeline.view(今天)` 按当前游戏日**现切窗口**
  （`date ≤ 今天` = 已发生；`今天 < date ≤ 今天+N月` = 预兆）。因此「放弃本轮」回滚时宏观视图随时钟自动回退，
  **无需任何标记**；作者改剧本对**所有存档立刻生效**、小模型不介入（宏观不能编歪）。

#### 存储

```
游戏数据/世界线程.json        ← live（在 游戏数据/ 下 ⇒ 自动进入"状态现拼"与开局快照）
    { 模拟游标,                                   # 世界推演进度（bookkeeping，不注入）
      人物线程: {名: {地点, 最新:{日期,地点,类型,顺利度,纳入上下文}, 流水:[...上限5]}} }
trpg-world/世界推演/宏观时间线.json   ← **只读剧本**（不落档；按当前日期现切窗口）
trpg-world/世界推演/推演规则.md
trpg-world/角色动态档案/{活跃,不活跃}/*.md   ← 近记忆文本（大模型读）
chroma                        ← 存档时蒸馏（大模型，重）
```

- **注入裁剪**：大模型看到两块——
  - `世界线程`：`world_threads.threads_view()`，只保留 `纳入上下文` 为真的条目，某人物若全被裁掉则不出现；
  - `宏观时间线`：`macro_timeline.view(今天)`，`宏观` = 近 N 月已发生（更早的已在 `gm_memory`）、
    `预兆` = 未来 N 月（仅供铺垫）。N 由 `TRPG_STATE_WINDOW_MONTHS` 调（默认 3）。
  - **存储始终全量**，宏观**不落档**（只读剧本现切）。

#### 大模型如何获知世界

1. **`世界线程.json` 及时可见**：被「状态现拼」自动纳入每次 LLM 调用；**宏观时间线**由只读剧本现切。
2. **NPC 登场即读档**：调工具 `get_character(name)` —— 返回**静态正典 + 动态近记忆**（活跃优先、退不活跃）。**深层记忆（`char_memory[owner]`）不由本工具取**——由 LLM 按需再调 `DB_query_tool`。

#### 硬依赖

- ✅ **时间必须权威**：规则已写入 `总览.md` 通用规则 10；`engine` 另加**机械兜底**——叙述若含时间推进标记（`翌日/次日/数日后/赶了N天/…`）却未调用 `update_time`，则在下一轮注入「时间提醒」直到补上。

#### 待定 ❓

- 活跃 → 不活跃的淘汰规则。🅿️ 搁置（等活跃 NPC 增多后再定）

### 5.7 信息边界（跨层原则）🚧

#### 问题

`history` 是全世界的真相，但**一个大模型同时扮 GM 与所有 NPC**，会把"梁峰私下做过的事"当成"NPC 也知道"。表现为 **NPC 全知 / 上下文泄漏 / 元游戏**（实测：出一趟远门回来，NPC 却知道你在外地干了什么）。

#### 原则：可见性是一条跨层统一的轴

| 层 | 隔离键 |
|---|---|
| `char_memory` | `owner` |
| `history` / `current.jsonl` | `在场` / `知悉` / `公开度` |
| `lore` 知识库 | `visibility: public / gm_only / char:<名>` |

#### 关键澄清：`在场` ≠ `知悉`

受害者、被事后告知者、听传闻者都构成知悉。故需三个概念：

| 字段 | 含义 |
|---|---|
| `在场` | 亲眼所见者 |
| `知悉` | 事后被告知/推断得知者 |
| `公开度` | `私密` / `传闻` / `公开` |

NPC X 的知悉集 = `在场∋X` ∪ `知悉∋X` ∪ `公开度≥传闻且能传到 X` ∪ `char_memory[owner=X]`；满足 **GM ⊇ 玩家/梁峰 ⊇ 每个 NPC**。

#### 已定 ✅：GM 叙述与 NPC 对白拆成两次调用（两段式）

理由：这是唯一能**物理隔离**知悉集的办法，不依赖提示词自觉（与§5.1"约束必须机械化"同源）。

```
玩家输入
   │
   ├─ Pass 1  GM（客观）  上下文 = 全量规则 + 全量 history + 状态 + 本场在场人
   │           产出 = narration（世界/环境/后果）+ 舞台调度（谁在场、谁开口、立场）
   │           ✗ 不产出 NPC 直接引语
   │
   └─ Pass 2  NPC（主观，每个开口者一次，可并行）
               上下文 = 规则 + 该 NPC 知悉集（过滤后的 history + char_memory[owner]）
                        + Pass 1 给出的"本场事实/自身立场"
               产出 = 该 NPC 的 chat（台词 + 表情）
   │
   ▼
合并：按舞台调度排序 → [narration..., chat...] 事件流
```

- 代价：每轮 N+1 次 LLM 调用（N = 本场开口的 NPC 数）。缓解：只对**实际开口**的 NPC 调 Pass 2。
- **GM 知道全部真相以推动世界，但不得让 NPC 说出其知悉集之外的细节**——两者在两段式里天然分离。

#### 待定 ❓

- **tag 从哪来**：让大模型输出 `{"type":"scene", ...}` 控制事件（便宜但会漏标）；或**小模型异步标注**（倾向：抽取而非生成，并入 `world_worker`）。
- **Pass 2 用哪个模型**：复用大模型保人物深度 vs 换更快模型。
- **传播机制**：`公开度` 随 `world_sim` 日推演演化（私密→传闻→公开，沿地理/关系网扩散 `知悉`）。
- **校验**：重要 NPC 对话事后用小模型核对是否引用知悉集外事实（不阻塞）。
- **数据模型**：`current.jsonl` 增加 `在场` / `知悉` / `公开度` / `scene_id`。

### 5.8 知识库层（正典检索投影）🚧

#### 定位：与记忆层性质相反

记忆是"世界**发生过**什么"（chroma 即真相源）；知识库是"世界**本来**是什么样"（**md 是真相源，chroma 是可重建投影**）。

| | 记忆层 | 知识库层 |
|---|---|---|
| 内容 | 本局发生的事实/认知 | 史实/正典/日常参考 |
| 真相源 | chroma 本身 | `trpg-world/考据/*.md` + 正典 |
| 写入者 | 存档蒸馏（LLM） | 构建脚本（代码） |
| 变化 | 每局增长/淘汰 | 稳定，人工维护 |
| 检索过滤 | `owner` | `domain` / `era` / `visibility` |
| 可否进游戏状态 | 可 | **绝对不可** |

#### 已定

- **独立库** `trpg-db/chroma_lore/` + `ingest_lore.py`（与 `init_GM_DB.py --reset` 隔离，互不误清）。
- **单 collection `lore` + metadata 过滤**（不拆多库，免 LLM 选库）：`source`（出处）/ `domain`（`daily`/`canon`/`history`/`geography`）/ `era` / `visibility` / `confidence`（`史料`/`二创`/`推测`）。
- **chunk 按标题切 + context 前缀**，单块 200–500 字；**事实卡片，不倒原文**。
- **只读工具** `KB_query_tool(query, domain, era, visibility, n)` → 返回**带出处**的片段；注册进 `registry.py`。
- **触发双轨**：LLM 主动调 + 引擎每轮预检索注入（规则层仍全量；正典只走检索）。

#### 铁律 🔒

1. KB 结果**永不写入** `gm_memory` / `char_memory`。
2. 注入时标注"这是**设定/史实参考**，不是本局发生的事"。
3. **无命中 → 明确兜底**（"考据未收录，按南宋常识处理"），**不允许编造**。

#### 与 web search

KB 优先（离线、可溯源、无年代泄漏、无剧透失控）。真接 web search 须独立管线、结果不进 chroma/游戏状态、强制年代过滤；默认不接。

#### 内容源

新建 `trpg-world/考据/`，从《梦粱录》《武林旧事》《蒙元入侵前夜的中国日常生活》等整理**事实卡片**；先索引现有 `trpg-world/` 正典跑通全链路。

## 六、连续时钟 v0.2（核心）

#### 动机

把游戏从"聊天框为主 UI"升级为"**世界为主 UI**"：地图是主界面（WASD 自由走），
按 Enter 才调 LLM 出场景。时间是这一切的骨架——**它必须自己流动**，而不是靠
`update_time` 一次次离散推进。

#### 6.1 数据模型：一个标量

```
单一真相源 = 一个单调递增的整数标量「游戏秒」（自纪元起）
其余全部派生：日期 / 时辰 / 刻 / 昼夜 / 季节 / 天气
```

**为什么不用维护日历对象**：**"过去"不需要时钟** —— `current.jsonl` 每行已带当时时刻。
标量只管"现在"，历史记录里存"那时"。

落点：`trpg-server/游戏数据/时钟.json`：`{ "游戏秒": 1234567, "状态": "running" }`。

投影到 `基本信息.时间`：`{日期, 时辰, 刻, 纪年, 干支}`——`纪年`/`干支` 是**给 LLM 看的**
（年号由后端裁决，不让模型猜）；`时钟.json` 本身**不进 LLM 上下文**（裸秒数徒增困惑）。

#### 6.2 状态机

```
RUNNING    探索 / 叙事（非 LLM 请求期）—— 实时流动
PAUSED     菜单 / 历史记录 / 窗口失焦 / LLM 请求窗口内
ACCRUING   战斗 —— 冻结实时流，按回合累积，结束时结算
```

| 模式 | 时钟 | 主交互 | LLM |
|---|---|---|---|
| 探索 | `RUNNING` | WASD / Enter | ✗ |
| 叙事 | `RUNNING`（请求窗口 `PAUSED`） | 行动 / 说话 / 继续 | ✓ |
| 战斗 | `ACCRUING`（回合折算） | 战棋 | 仅思路判定 |
| 菜单 / 历史 / 失焦 | `PAUSED` | 面板 | ✗ |

**速率**：默认 **1 真实分钟 = 1 刻（15 游戏分钟）**，即 1 游戏日 = 96 真实分钟；
`TRPG_CLOCK_RATE` 可调，`TRPG_CLOCK=0` 关闭（对照旧行为）。

| 参考 | 数值 |
|---|---|
| 1 游戏日 | 96 真实分钟（1.6 小时） |
| 白天→黄昏 | ~48 真实分钟 |
| 走完全城（约 2 刻路程） | ~2 真实分钟 |

#### 6.3 两个显示粒度（关键）

| 用途 | 粒度 |
|---|---|
| 存储（真相源） | **秒**（整数，避免浮点漂移） |
| **发给 LLM** | **刻**（粗，防微抖动干扰模型） |
| 前端古钟动画 | **秒**（细，钟要"会动"） |

> ⚠️ **发给 LLM 只用刻级**。否则每轮时间差几秒，模型会困惑"时间怎么一直在跳"。**UI 细、LLM 粗**。

#### 6.4 前端插值（别每帧轮询后端）

```json
// 后端给一次锚点
{ "游戏秒": 1234567, "服务端墙钟": 1726900000.0, "状态": "running",
  "倍率": 15, "显示": {...}, "纪年": "嘉定十三年正月十六", "干支": "庚辰年" }

// 前端本地插值（requestAnimationFrame）
当前游戏秒 = 游戏秒 + (Date.now()/1000 - 服务端墙钟) × 倍率   // 仅 RUNNING
```

- 每次 `/action` 响应**顺带带一份新锚点**重新校准（防漂移）。`PAUSED` 停插值，`RUNNING` 重设锚点。
- 古钟组件**只更新一个 CSS 变量**，不要每帧 `setState`。
- 实现：**惰性求值，不跑后台线程**：`running` 时 `now = 锚点秒 + (墙钟 − 锚点墙钟) × 倍率`；其余状态冻结在锚点秒。

#### 6.5 与现有系统的联动

| 系统 | 改动 |
|---|---|
| `update_time` | **降级**为"叙事跳时"通道（睡一夜 / 赶路三天）；环境时间由时钟自动推进 |
| 时间权威护栏 `engine._check_time_authority` | **换语义**：叙述有大幅跳时却没调 `update_time` → 提醒（待做） |
| `weather_system` | ✅ 时钟**跨游戏日**时自动切当天天气（`time_flow.pump()`） |
| `world_worker` | ✅ 时钟**跨日**时入队（`MAX_TICKS=10` 兜底挂机跨多日） |
| `精力`（`状态.json`） | ✅ 跨**时辰**随昼夜流逝（夜时辰熬夜更狠）；工具 `sleep` 推进并恢复 |
| `save_pipeline` | 快照 + 分段誊写使用连续时钟 |
| `GameSession` 快照 / `abandon` | 快照必须含时钟标量 |

**时间双通道模型**：

```
环境时间（走路 / 说话 / 观察）  ←  时钟自己流
叙事跳时（睡一夜 / 赶路三天）    ←  LLM 调 update_time
```

#### 6.6 为何"LLM 请求窗口暂停"

`TurnRunner.run` / `run_save` 期间 `clock.pause("turn"/"save")`，返回后恢复。
生成延迟**不计入**游戏时间——玩家不为模型的慢买单；但窗口之外的叙事/探索时间照流。

#### 6.7 年号 / 干支：收归后端

**原则**：年号是**硬事实**（总纲第 5 条），不让模型自己猜（它会说错朝代纪年），也不能前后端各维护一份。

- **唯一真相源**：`game_clock.ERAS`（**南宋全表** 1127 建炎 ~ 1279 祥兴，22 个年号）；`era_name` / `ganzhi_year` / `cn_number` / `cn_day` / `chinese_date` / `render_era`。
- **给 LLM**：`_sync_locked` 把 `纪年`（"嘉定十三年正月十六"）与 `干支`（"庚辰年"）写进 `基本信息.时间` → 随「状态现拼」自动注入。
- **给前端**：`GET /clock` 锚点含 `纪年` / `干支`；前端**不再自备年号表**。
- **重叠年**（1276 德祐/景炎、1278 景炎/祥兴）：取**起始年最新**的年号，使每个年号都有「元年」。
- 超出南宋 → `公元1220年`；`recap` 也改用 `render_era`。

#### 6.8 时间流逝的后果（`tools/time_flow.py`）

时钟只管"时间"，`time_flow` 管"后果"：

```
pump()   ← 在 /clock、/state、/action 里调用（前端每 60s 轮询 /clock → 挂机也跨日）
  ├─ 跨时辰 → 精力随昼夜流逝（夜时辰 子/丑/寅 = 熬夜，扣得更狠）
  └─ 跨日   → 切当天天气（weather_system）+ 触发世界推演（world_worker）
rest(时辰)   ← 工具 sleep
  └─ 先 pump 结算清醒时段 → 推进时钟 → 睡眠时段按「恢复」而非「消耗」结算
```

- **跨时辰/跨日检测**：`clock.take_crossings()`（全局刻 / 日游标；首次只对齐不结算；时间设回过去则重新对齐；大跨度只结算最近 96 时辰）。
- **数值**：`trpg-server/时间影响.json`（改文件即时生效）：`每时辰精力.昼/夜`、`睡眠回满时辰`（每时辰恢复 = **精力上限 ÷ 该值**，随养成自动变强）、`夜时辰`。
- **工具 `sleep(时辰)`**：睡觉推进时间 + 恢复精力；`say`/`gm` 回合被护栏驳回。

## 七、三模式状态机（探索 / 叙事 / 战斗）

```
        ┌────────────────────────────────────────────┐
        │              探索模式（地图）                │
        │  WASD 自由走 · 时钟 RUNNING · 无 LLM          │
        └───────┬──────────────────────────┬─────────┘
                │ 玩家输入（行动/说话/继续/主持人）│ 敌对
                ▼                          ▼
        ┌───────────────────┐      ┌───────────────────┐
        │   叙事模式（场景）  │      │   战斗模式         │
        │  背景图 · LLM · 钟 RUNNING（请求窗口暂停）│  回合制 · 钟 ACCRUING │
        └─────────┬─────────┘      └─────────┬─────────┘
                  │ 主持人裁定 resume_exploration │ 战斗结束
                  └──────────────┬────────────┘
                                 ▼
                            回到探索模式
```

### 核心决策

**进入叙事由玩家发动，退出叙事由主持人裁决。** 这样玩家在叙事中**不能**自行在地图上乱走，
除非先向主持人说明「我要走了」——正是设计意图。约束靠**模式本身**（叙事下根本不渲染地图），
而非提示词自觉（与§5.7 信息边界同源：约束必须机械化）。

### 实现

- **前端**：`GameController.gameMode: "explore" | "narrative" | "battle"`。
  - 探索 = `<GameMap zoom={18}>`（`Map.tsx` 的 `onMove` / `playerOverride` / `extraFootprints`）；
  - 叙事 = `GameScene`（探索时 `display:none` 隐藏但**不卸载** → 叙事进度不归零）；
  - 战斗 = `BattleScene`。
- **切换**：
  - 探索 → 叙事：`sendAction` 时带 `坐标`（光标）+ `上一坐标`；发出后 `setGameMode("narrative")`；
  - 叙事 → 探索：工具 `resume_exploration` 产出 `ui_event("mode", mode="explore")`，前端 `kind:"mode"` 处理；
  - 战斗：`start_battle` → `kind:"battle"`。
- **坐标 → 硬事实**：`main._apply_move()` 调 `update_location`（更新位置 / 足迹 / 城内城外 / 方位），并把 **【移动】梁峰自「A」来到「B」，相距约 N 米。（耗时提示）** 注入本轮 `pending_notes`——承总纲第 5 条。
- **协议**：`ui_events.KINDS` 加 `mode`；`总览.md` 通用规则 14 说明三模式。

### WASD 连续移动

`Map.tsx` 的 `ExploreControls`：
- **命令式 Leaflet**：玩家标记用原生 `L.marker`，rAF 逐帧 `setLatLng` + `map.panTo` 相机跟随—— **不触发 React 重渲染**；
- **速度与时间挂钩**：真实速度 = 游戏内步速 `× 时钟倍率`（时间快 N 倍，标记也快 N 倍，游戏内步速才真实）；按住 Shift ×2.6 奔跑；
- 位置真相在 `posRef`（每帧读写）；**松开按键**时才回调父组件（同步迷雾轨迹 / 行动坐标）；
- 输入框聚焦时不拦截 WASD（打字不移动）。

### 上一轮状态 + 当前状态（供模型自行对比）

`engine.state_stack = deque(maxlen=2)`（**长度上限 2、不累积**）：每轮末 `append(本轮状态)`，
下一轮把栈顶（上一轮）与现拼的「当前状态」**一起**发给 LLM，模型自行看出时间 / 地点 / 数值的变化，**代码不算差值**。

## 八、地图为主 UI + WASD 探索

### 8.1 渲染：保留 Leaflet，加一层 Canvas

Leaflet 是**地图库**不是游戏渲染器。WASD + 碰撞 + 动画下它会吃力，但**不推倒它**
（瓦片、点击层、迷雾、`/explored` 都在上面）。方案：

```
Leaflet（瓦片底图 + 坐标系）        ← 保留
  └─ Canvas Overlay（rAF 游戏循环）  ← 角色 / NPC / 特效 / 碰撞可视化
```

### 8.2 碰撞：前端矢量判定（已实现）

WASD 自由移动必须阻止穿墙 / 穿屋 / 入河。**已实现为前端矢量碰撞**（地形数据由空间库导出）：

- 新增 `trpg-client/src/in-game/walkable.ts`（前端矢量判定 + 网格索引）
  与 `trpg-map/draw_tiles/export_walkable.py`（从空间库导出 `trpg-client/public/data/walkable.geojson`）。
- 规则：除**水域 / 城墙**外可走；**城门 25m** 为出城通道；**桥 100m** 可走；**路 ∩ 水** 默认路可走。
- `ExploreControls` 走不动时**沿障碍滑动**（先试 X、再试 Y）；被挡时棋子描边转灰；`?nowalk=1` 关闭碰撞。
- **城门限时（新）**：`营业时间.json` 把城门定为 `卯-申`；`export_walkable.py` 导出城门 hours，前端按当前时辰判断开闭——**闭门后走不了城门**（城墙依旧阻挡）；`query_place/query_nearby` 结果带 `营业时间`+`现在`。

> 现有 `map_spatial.db` 只有几何、未成图。后续可升级为真正的路网图（Dijkstra/A*）；语义可复用战斗的 `blocked()` / `reachable_cells()`。

### 8.3 相机与控制

- 相机跟随角色；WASD 产生 `MoveVector(x,y)`。
- **走路只更新坐标 / 时钟 / 足迹，不写 `history`**（否则 `current.jsonl` 被脚步刷爆）。
- 输入抽象层（键盘 / 手柄 / 语音）为后续留口。

### 8.4 Enter 进入场景（代码注入地理硬事实）

按 Enter / 点击输入时，**代码先自动跑地理查询**，再让 LLM 生成场景：

```
玩家输入
  → 代码：query_nearby / city_context / description / place_notes / 当前时刻 / 天气
  → 拼成「此地是什么、旁边有什么、什么时辰、天气如何」
  → 注入 prompt → LLM 生成叙事
  → 前端切到对应背景图（由坐标 / 地点类型确定，不再靠小模型猜）
```

- 这是**总纲第 5 条**的直接应用。背景图改为**由坐标 / `ancient_kind` 确定性映射**。
- 场景必须有**显式出口**（「离开」按钮 / 主持人裁定），不能只等 LLM 说"你可以走了"。
- **已落地形式**：`main._apply_move()` 在玩家输入时注入【移动】系统提醒。

### 8.5 足迹的复用

`游戏数据/足迹.json` 现为 `{"points":[{lon,lat,地点}]}`。

| 层级 | 用途 |
|---|---|
| **MVP** | 迷雾揭示（已有）+ 轨迹可视化 |
| **亮点** | **足迹 = 在场追踪**：WASD 走过某处，附近 NPC 自动记为「在场」→「知悉」 |

> **为什么是亮点**：这顺手解决了最大技术债之一（§5.7 信息边界的"在场"标注）。机械、免费、确定性。

⚠️ **必须降采样**：WASD 每秒产生几十个坐标。按网格去重（2m 格）/ 最小距离阈值（10m）/ 设上限 + 老化。

## 十、战斗系统

> 设计详见 `trpg-world/战斗系统.md`；本节记架构决策与数据链。

### 决策（v0.1 ✅）

- **战斗是独立子状态机，不复用 GM 工具循环**：`/battle/*` 自成一套（HTTP），战斗推进不经 `/action`。
- **事件边界**：GM 只在两处介入——①开战（工具 `start_battle` → UI 事件 `kind:"battle"`）②结束（结果 → `pending_notes` → 下一轮 GM）。**战斗过程不调用大模型叙事**（快）。
- **硬事实全归代码**：命中 / 伤害 / HP / 内力 / buff / 移动 / 射程 / 胜负 全在 `tools/battle.py`；**模型没有任何数字输出权**。
- **AI 只做两件事**：①判玩家「思路」→ 只出「评价」枚举，代码查表成修正（只作用于伤害）；②阵营决策 → 只出 `{动作,目标,移动}`，代码校验降级。
- **模型可切**：思路判定默认小模型、战斗界面内可切大模型；设置存 `sessions/battle_settings.json`（**不进 `游戏数据/`、不进每轮状态块**）。
- **模拟战斗**：环境设定里直接开局，`模拟=True` 时不回写真实 `状态.json`，且结果**不注入**下一轮叙事。
- **NPC AI 全归代码**（战术层 L2 枚举+打分 + L3 `clone` 前瞻）；`TRPG_BATTLE_AI=model` 可切回小模型。
- **定位**：**TRPG 主干 + 战棋战斗模块**；选定路线 B「深化为真战棋」（见 `TODO.md`）。

### 分层与数据链

```
前端 battle.tsx ──HTTP──► main.py /battle/* ──► battle_session（单例/生命周期/写回）
                                                      │
                                        battle_runner（阶段机 + 战局快照）
                                                      │
                                   ┌──────────────────┴──────────────────┐
                                   ▼                                     ▼
                            battle_ai（AI）                        battle（数值·纯代码）
                                   │                                     │
                            小模型 / 大模型                    读：状态/属性/基本信息/招式表/武力排名
```

### 一回合

```
begin_round（定先手 + DoT + 内力回复）
  → 先手方阶段：玩家先动（判思路）→ 该侧 NPC 一次
  → 后手方阶段：另一侧
  → end_round（buff 计时）
```

**每回合 ≤ 3 次模型调用**（玩家判定 1 + 友方 1 + 敌方 1；思路为空则 0 次判定调用）。

### 命中 / 伤害（实现版）

```
命中 = d100 + clamp(round((攻方兵器 − 守方轻功)/5), ±25) + 命中buff + 位置(背袭+15/夹击+8)
       <20 落空｜20–59 ×0.8｜60–89 ×1.0｜≥90 会心 ×1.5
伤害 = 威力 × 兵器/100 × 梯度系数 × 武器类型(利器1.25/钝器1.0/徒手0.9)
     × 五行克制(克1.3/被克0.8) × 位置(背袭1.3/夹击1.15)
     × (1 + 思路修正/100) × buff − 减伤
```

### 数值要点

- 网格 **10×6**（切比雪夫距离）；先手方→后手方**阶段制**；玩家 **6 动作**：移动 / 舞剑（普攻不耗内力）/ 防守 / 技能（五行）/ 交流（队友或对手）/ 撤退。
- **五行相克**；**武器类型**（利器×1.25+流血 / 钝器×1.0+会心眩晕 / 徒手×0.9）。
- **Buff**：流血 / 中毒 / 内伤 / 破绽 / 眩晕 / 护体 / 士气 / 动摇 / 致盲 / 洞察 + 蓄力 / 穿甲。
- **地形**：`Battle.terrain` + `blocked()`（房屋/墙阻挡，河可涉水）+ `reachable_cells()`；`state()["地形"]`。
- **技能 AOE**：`skill_centers/skill_area/_is_aoe`，以所选格为中心、半径 N 内。**技能速记**：舞剑=普攻不耗内力；水天一色=自身·洞察（命中+30 / 会心线−15，2回合）；生生流转=自身·蓄力（≤3层）；胧/冰=选格 AOE。

### 数据写回

- 战斗状态**只在内存**（`battle_session._RUNNER`），不落盘。
- 结束 → 玩家 生命/精力/伤势 → `游戏数据/状态.json`（模拟战斗跳过）；结果摘要 → `session.pending_notes` → 下一轮注入 GM。

### 前端

`in-game/battle.tsx` + `styles/Battle.css` + `in-game/BattleBoard.tsx`（等轴测 SVG 2.5D：人物=锥+球、房/墙=长方体、河=凹陷、树）：10×6 网格 + 动作菜单 + 目标点选 + 思路输入框 + 滚动日志 + 顶部小/大模型开关 + 结算浮层；主菜单「环境设定」可开**模拟战斗**（`GET /battle/roster` → `POST /battle/sim`）。

## 十三、前端 / 世界观文档 / 地图

### 13.1 前端（`trpg-client/src`）

- **顶层按钮**：主持人 / 行动 / **说话**（对 NPC 的台词）/ **继续**（时间流逝、世界推进）/ 历史记录 / **数据**。

### 13.4 地图性能（探索模式卡顿）定案

> 症状：「走过的地方流畅，新走的地方卡」；菜单地图（无 WASD）全渲染也流畅。

**逐层关测结论**：

| 测试 | 结果 | 结论 |
|---|---|---|
| `?nohit=1`（关命中层） | **不卡** | → **HitLayer 是主因** |
| `?noicons=1`（关图标层） | 卡 | 图标层不是主因 |
| `?nopan=1`（关相机） | 稍有掉帧 | 相机次要 |
| `?nofog=1`（全渲染） | **最流畅** | 迷雾让 `data` 频繁变 → HitLayer 重建 |

**根因**：`HitLayer` 的 effect 依赖 `[map, data, extents]`；迷雾开着时每走一段 `visibleFeatures` 就是新数组 → `data` 变 → **整个 canvas 图层被拆掉重建**（新建 `L.canvas()` + `clearLayers()` + `addData()` 几百个 `L.Path`）。

**已修**：`HitLayer` 重写——图层只挂一次（`useEffect([map])`，`data`/`extents` 走 ref）、`Map<Feature, L.Layer>` 增量增删、renderer 只建一次；`render(mode)`：`viewport` / `data` / `clear`。同时修了「图标缓存键不含 URL → 先画兜底圆点后无法恢复」的 bug。

**逐层开关**（URL，可叠加，HUD 显示当前关项）：`?noicons=1` `?nohit=1` `?nopan=1` `?nofog=1`。

**残余**：`?nopan=1` 仍稍有掉帧，疑为**瓦片首次加载 / 首次放大合成**（假设 A/D），未处理。可选：前端预热（`new Image()` / `img.decode()`）或生成城区 z17/z18（±5km ≈ 45MB）。

**调试 HUD**（`Map.tsx` 顶部 `DEBUG_HUD`，挂 `document.body`）：FPS / 最差帧 / 图标数 / 命中数 / 可见数 / 两层重绘耗时。

#### 血泪坑（勿重踩）

1. **不要给 Leaflet 的 pane 加 `will-change`**——直接黑屏（瓦片放大 4 倍 + 几百 marker 吃满显存）。
2. **Hooks 绝不能放在 early return 之后**——直接白屏（"Rendered more hooks than during the previous render"）。
3. **改 hook 顺序后必须硬刷新**（Ctrl+Shift+R），否则 HMR 失效。
4. **不要每帧 `panBy`**（内部会 `fire('moveend')` → Canvas 矢量层全量重绘）；相机用 `map._rawPanBy()`（Leaflet 私有 API，需强转）+ **整数像素**。
5. 原地 push 的数组若下游用 `useMemo`，必须有版本号才会重算。
6. 探索模式迷雾**不用 `足迹.json`**（用户明确要求），用玩家位置单点气泡 `focus`；旧足迹代码路径已不走。
7. 菜单地图的 `showAllIcons`（全部 POI 都画）是明确功能，别当 bug 删。

### 16.11 NPC 唯一姓名（2026-09-17）

- **策略**：每个有实质互动的 NPC 都有**独一无二的正式姓名**（姓＋名 / 名号），**不用职业/身份代称**做名字。

## 十七、已知问题 / 坑

### 17.1 运行与数据

1. **别用外部工具（DB Browser 等）打开 `chroma_db`**：chromadb 的 Rust 内核启动要拿写锁，被占会**静默卡死、无任何输出**。
2. **`游戏数据` 文件的并发写**：Flask 多线程下 `open()` 读与 `os.replace` 可能撞 `PermissionError: [WinError 5]`；已修（同锁 + 唯一 tmp + 重试 + 副作用不 500）。**别用编辑器/数据库工具开着 `游戏数据/*.json`**。
3. **只跑一个后端**：开两个 `python main.py` 会抢 5000 端口 / 一个跑旧代码，表现为"改了没生效 / 有的对有的不对"。
4. **重启生效**：改 `trpg-server` 的 `*.py` 或前端 `*.ts` **必须重启**对应进程；改规则 md / `时间影响.json` 免重启（热读）。
5. **数据目录在 `trpg-server/` 下**（`游戏数据` / `天气数据` / `归档存档` 与 `tools/` 同级）。
6. **小模型单次 10s 硬超时**；`lmstudio.set_sync_api_timeout()` **不管用**。

### 17.2 规则 / 逻辑

7. **时间必须权威**：任何"过夜/赶路"叙述必须调 `update_time`（规则 10）；`engine` 有机械兜底。
8. **`history` 无滑动窗口**：长局会让每轮携带的 history 变长（推高 token / 首字延迟）；用户称上下文足够大，**暂缓**（见 `TODO.md`）。
9. **足迹不发 LLM**；**时钟.json 不发 LLM**。
10. **`update_time` 语义漂移**：环境时间自动流后，护栏须从"推进了没落库"改为"**大幅**跳时却没落库"（待做）。
11. **挂机跨多日**：`world_sim` 靠 `MAX_TICKS=10` 兜底；失焦暂停是主要防线。
12. **`file_tools` 已默认禁用**；`游戏数据/` 只能走专用接口。
13. **工具返回类型不统一**（str / dict / int / list）——目前都能被 `json.dumps`，新工具需注意。

### 17.3 前端 / 地图

14. **不要给 Leaflet pane 加 `will-change`**（黑屏）；**Hooks 不能在 early return 后**（白屏）；改 hook 顺序必须硬刷新。
15. `_rawPanBy` 是 Leaflet 私有 API，需强转；**不要改回每帧 `panBy`**。
16. 地图无 z17/z18 瓦片，z18 是 z16 放大 4 倍；残余掉帧疑与瓦片首次加载/合成有关（§13.4）。
17. 放弃确认仍是原生 `window.confirm`（待换自定义浮层）。

### 17.4 内容 / 世界观

18. **地图缺史实城门**：现只有 7 座城门（「水门」在城东北），**无「西水关」**等史实水门；GM 曾借水门当西水关。需改地图源并重建。
19. **地域特色未做**：`build_world.py` 同一套算法，所有城市必然长得一样（见 `TODO.md`）。
20. **素材版权**：若日后封装发行，BGM / 背景图 / 地图数据（OSDbL）须先确认授权。
21. **内容生成型骰子已停用**：`daily_event_dice` / `travel_event_dice`（规则移入 `trpg-world/废弃/`、工具进 `_DISABLED`）；
    `游戏数据/混乱度.json` 因此成**孤儿**（原来只被这两者读取），需重定位或一并废弃。

## 十九、路线图（MVP 边界 / Phase 2-3 / 验收）

### 19.1 v0.2 MVP 边界（实施状态）

```
✅ 单一标量时钟（整数游戏秒）—— tools/game_clock.py
     ├─ RUNNING / PAUSED / ACCRUING（三态）
     ├─ RUNNING：探索 + 叙事（LLM 请求窗口内 PAUSED）
     ├─ PAUSED：菜单 / 历史 / 失焦
     ├─ ACCRUING：战斗（begin/end_battle 已就绪，**战斗流程尚未接入**）
     └─ 快照 + 存档含标量；时钟.json 不进 LLM
✅ 状态现拼：每轮注入 基本信息.时间（刻级 + 纪年/干支）
✅ 上一轮状态 + 当前状态（state_stack，长度 2）
✅ 左上角古钟（SVG + rAF 插值；探索模式也显示）
✅ 年号 / 干支（南宋全表 1127~1279，收归后端）
✅ 时间影响数值：跨时辰扣精力（夜时辰更狠）+ sleep
✅ 跨日联动：切当天天气 + 触发世界推演
✅ 三模式状态机（探索 WASD / 叙事 / 战斗）
✅ 探索坐标 → 叙事：【移动】系统提醒
✅ 窗口失焦自动暂停
✅ WASD 碰撞（水域/城墙；城门限时）
❌ 未做：战斗时间折算接入、/move 边走边同步、手柄、语音、
        NPC 地图标记、昼夜光照、在场追踪、农历/节气、转场动画
```

> **与最初计划的偏离**：
> - 原计划「Enter 锁定点位 → 触发场景」改为 **WASD 自由走 + 按钮输入**；
> - 原计划「场景离开按钮」改为**主持人裁定**（`resume_exploration`）；
> - 「Enter 场景 + 地理硬事实注入」以 `_apply_move` 注入【移动】提醒的形式落地。

### 19.2 Phase 2 / 3

> ⚠️ **Phase 2 是这次改革的"完成标准"，不是可选项**。否则 Phase 1 只是"能走路的场景选择器"。

**Phase 2（让地图活起来）**
- `world_sim` 人物线程 → **地图 NPC 标记**（移动 / 聚集 / 离散）
- `place_notes` / `description` → 地点气泡
- **环境事件层（替代骰子）**：地点定时事件（`place_notes` / `宏观时间线`）到点触发 + NPC 在场（`world_sim`）
- 昼夜光照 + 按时辰开关的铺子 / 夜市
- **足迹 → 在场追踪**（接信息边界）

**Phase 3（打磨）**
- 转场动画、音效、时间压力机制（可选）
- 手柄支持（Gamepad API）、语音输入（STT → `/action`）
- 农历 / 节气 / 节日 / 月相

### 19.3 验收标准

**时钟**
- [ ] 探索模式下站着不动，古钟持续走；打菜单 / 看历史 / 切窗口 → 停；关掉 → 续走。
- [ ] LLM 请求进行中，钟不跳（请求耗时不计入游戏时间）。
- [ ] 战斗结束，时钟一次性 += 回合数 × 每回合秒；跨时辰 / 跨日正确。
- [ ] `/action` 每轮的 prompt 里时间**只到刻**；UI 古钟**平滑到秒**。
- [ ] 存档 → 读档，时钟标量一致。

**地图 / 移动**
- [ ] WASD 能走，撞墙 / 撞屋 / 入河被挡；闭门后走不了城门。
- [ ] 相机跟随角色；走路**不产生** `current.jsonl` 行。
- [ ] 足迹增长受降采样限制（不随步数线性爆炸）。

**场景**
- [ ] 输入时 prompt 含**代码注入**的 `query_nearby` / `city_context` 结果（非模型编造）。
- [ ] 背景图由坐标 / 地点类型确定，同一地点可复现。
- [ ] 「离开」按钮能回地图。

**联动**
- [ ] 时钟跨游戏日 → 天气自动切换；`world_sim` 入队。
- [ ] 叙述"睡了一夜"却没调 `update_time` → 下一轮出现时间提醒。
