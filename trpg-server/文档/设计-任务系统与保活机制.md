## 〇、一句话

**世界有自己的起承转合（弧）；玩家看得见的是任务；NPC 的档案在"还在说话"期间被保活；好感度由存档结算。**
LLM 短视、无长程规划 → "转/合"必须由外部机制逼迫，不能靠模型自觉。

## 一、三层关系（先立骨架）

```
故事大纲（作者 · 含剧透）
  └─ 弧 Arc：起承转合的形状            ← 导演维护 · GM 看不到      【上层，本文暂不细化】
       └─ 节拍 Beat：这段时间世界必须发生什么
            └─ 任务 Quest：玩家可见的目标 + 里程碑 + 时限   ← 本文范围
```

- **弧** = 隐藏的形状；**节拍** = 硬指令；**任务** = 弧对玩家的可见接口。
- 玩家完成 / 失败 / 过期 → 手伸回弧里推动相位。
- **时限 = 强制"转/合"的机械装置**：玩家拖到时限，世界替他翻页（补上 LLM 不会主动收线的短板）。

## 二、保活机制 【已定】

### 为什么

实测（`开发/verify_get_character.py`，10 次真实 DeepSeek 调用）：

| 场景 | 结果 |
|---|---|
| 首次登场（6 个 NPC） | **6/6** 调 `get_character(名)` |
| 连续对话（2 个） | **2/2 重新调**——因为工具消息不进 history，它不记得调过 |
| 无档案路人 | 1/1 正确未调（改用 `query_place`） |
| 在场不新登场 | 1/1 **多余调用**（思考原话：「我之前已经调过吗？没有实际调用」） |

结论：**它每轮都会把档案拉进上下文**（多一次 LLM 往返），而且判断不稳（该省时不省）。
既然内容反正要进上下文，不如由**代码确定性地常驻**——省往返、省延迟、降格式漂移风险、不依赖 GM 自觉。

### 规则

- **保活集**（引擎侧、按局）：成员 = **说过话的 NPC**（只认 `chat` 的 `speaker`）。
- **更新时机**：每轮 `_run` 结束后扫描本轮 `chat` 发言人 → 记 `最后发言轮`；其余成员静默轮数 +1。
- **掉出**：连续 **3 轮** 没说话（静默轮数 ≥ 3）→ 移出保活集（"停止保活"）。
  （发言轮本身计入，即发言后还会被保活 2 轮；第 3 轮静默起不再注入。）
- **不设上限**（可能很多在场 NPC，token 随人数增长，用户接受）。
- **注入位置**：`build_messages` 里放在**当前状态块之后**（tail，不破坏稳定前缀）。
- **注入内容**：**全量** —— 静态档案 + 动态档案 + `好感度 / 档位`。
- **首次登场仍走 `get_character`**（保活集是"上几轮说过话的人"，新面孔还不在此列；工具循环里 GM 会调，实测 6/6）。
  → 保活消除的是**重复抓取**（第 2、3 轮及"在场不说话"的冗余），不是首次查阅。
- **`get_character` 保留**为兜底（不在保活集里的、或要查深层 `char_memory` 的）。
- **不持久化**：重启后从 `current.jsonl` 最近几轮的 `chat` 发言人重建保活集。
- 档案按 mtime 缓存（一局内档案只在存档时变，几乎零 churn）。

## 三、好感度 【已定】

### 名字与范围

- 旧称"情谊"**废弃**，一律叫 **好感度**。
- 数值 **-100 ~ +100**（有失去才有重量）。

### 数据：并入角色档案（**不再单独建 `关系.json`**）【已定】

按 静态/动态 分层拆开——**不新增文件**（静态档案 55 份本来就在）：

**① 好感度 → 动态档案 §9**（会变；存档结算写这一行）

```
## 9. 与梁峰关系

- **好感度**：42（相熟）

### 里程碑
…
### 最近互动
…
### 态度
…
```

**② 立场档案 → 静态档案**（"她是谁"，建档时定、少变；供 GM 演人 + 存档结算判分）

```
## 8.5 立场

- **所属**：白鲨帮
- **主张**：抗倭护海民，与官军、朝廷为敌
- **底线**：背叛白鲨帮；与官军勾结
- **偏好**：义气、豪爽、并肩抗倭、骂官军
- **反感**：与官军交好、畏缩、看不起海寇
```

- **唯一机械需求**：`好感度` 必须是**代码可解析**的一行（前端显示、门槛判定）。
  **格式由 `character_archive.py` 统一生成**，模型只提供数字，不自由发挥格式（避免写成"很高"）。
- 代码读：`character_archive.read_affinity(name)`；前端走 `GET /relations`（扫 `角色动态档案/活跃/*.md` 的 §9）。
- 档位派生：+80~100 生死之交 / +60~79 挚友 / +40~59 相熟 / +20~39 相识 / -19~+19 陌路 / -39~-20 嫌隙 / -59~-40 敌视 / -100~-60 仇敌。
- 好处：与 §9「态度」同处一栏，**不再有第二个真相源**；保活注入本来就读整份档案，好感度顺带就到 GM 手里。

### 变更时机：**存档统一结算** 【已定】

- 局内**不实时加减**（避免每回合小模型的误动；`relation_sim` 管线**不建**）。
- 存档蒸馏回合（已有）扩展 `update_character_archive(..., 好感度变化=±n)`（存档专用）：
  - 模型给**增量 delta**（带每局上限，如 ±20）→ 代码读当前值、clamp(-100~100)、写回 §9 那一行；
  - 存档管线本来就在逐角色调该工具（写 §9 态度 / §10 情感记忆），顺手结算，不多一次调用。
- **语义澄清**：这里用大模型是**事后复盘**（存档蒸馏），不是局内那个正在演戏的 GM；
  局内 GM **没有任何好感度工具**（不给，防自判），只**只读**。

### 投递

- **保活注入**（在场上说话的 NPC）+ `get_character` 返回（首次/按需）→ 都带 `好感度 / 档位`。
- GM 每轮都能看到在场 NPC 的当前值，演得一致。
- 前端：`GET /relations` 扫活跃动态档案、解析 §9 的 `好感度` 行，**只显示好感度 + 档位**；
  立场/偏好/底线**不暴露给玩家**（会剧透人设）。

### 来源

| 对象 | 立场档案（静态 §8.5）从哪来 |
|---|---|
| 正典 55 人 | 从现有静态档案一次性抽取 + 人工校对 |
| GM 新造 NPC | 首次建档时随 `static` 写入 |

## 四、任务系统 【已定】

### 生命周期：机会 ≠ 任务

```
世界上的「事」（机会）——一直发生，可自行发展/消失，任务栏里没有
        │  玩家看见 / 被卷入
        ▼
   梁峰「答应 / 迈出第一步」   ← 唯一分界点
        │
        ▼
   【任务】上榜 —— 从此有时限、可追踪、前端渲染、过期会被销毁
```

- **没承诺的，永远不是任务**（世界照样走自己的结局）。
- **初始任务例外**：由作者写好，**开局就挂任务栏**（否则玩家"方向太多 = 没方向"）。
  - 当前演示引子：梁峰自枣阳逃难至扬州、投旧亲戚、问父母消息。
- **后续任务由 GM 在承诺那一刻创建**。
- **不设"放弃"动作**：不管就是不管 → 自然过期。
- **所有任务都必须有时限**（否则"不管"永远不了结）。

### 数据：`游戏数据/任务.json`

- **不分主线 / 支线**：世上没有这种分别，一律叫「任务」。
- **不拆子任务**：一个大目标 = **一条任务 + 若干里程碑**；里程碑**并列**（一轮可完成多条）。

```jsonc
{
  "id": "q_wen_missing",
  "标题": "查明失踪的姑娘们",
  "状态": "进行中",                   // 进行中 / 已完成 / 已过期
  "可见": true,
  "描述": "锦香宫两名女子一夜未归，温夫人不许声张。",
  "里程碑": [{"项": "去城西打听", "状态": "未完成"}],
  "时限": {"类型": "绝对", "游戏秒": 1466200, "显示": "嘉定十三年正月二十 · 戌时前"},
  "失败后果": "两人已被转卖出城，再无音信",   // 隐藏（DDL 裁定用）
  "创建于": "...", "更新于": "...", "归档于": null
}
```

- **时限由"具体那件事"决定，不设统一粒度**（孩子走失→天亮前；交货→三日后；仇家上门→今夜子时）。
  GM 创建时换算成**游戏秒**（挂连续时钟这个真相源）。
- **失败后果**必须在创建时/结算时写清（"玩家没做到，世界会变成什么样"），否则过期毫无重量。

### 过期时序（硬事实由代码，内容由 AI）

```
time_flow.pump()（/state、/clock、/action 都会跑）
   → 代码查：任意 quest.时限 <= clock.seconds()
      ① 状态 → 已过期；移入"已了结"归档（不硬删）
      ② 失败后果交给 world_sim → 世界推进一步
      ③ 弧相位推进
      ④ 注入 pending_notes：「【任务过期】…请据此叙述梁峰得知后的场景」
```

### 完成判定：里程碑耗尽 → 旁路大模型裁定 【已定】

- 小模型**不判完成**，只报「本轮新做到了哪些里程碑」（**并列**：报几条标几条，不要求顺序、不 cover 中间）。
  - **异步**：判定走后台队列（`quest_sim.run_async`），结果 `ui_events.push` 由下次 `/action` 或 `/state` 携回，不拖慢回合。
  - **模型**：默认路由**远端强模型**（`配置/小模型.json` 的 `quest` 段，OpenAI 兼容端点）。
    本地 4B 只会关键词对齐（叙事「追问但对方含糊没说出」也被判完成），语义判断不足；
    `provider=local` 或远端失败（`失败回退本地=true`）时才用 4B。
  - 给它的上下文：任务 `描述` + 里程碑现状（✓/○）+ **`真相` / `结局` 作【幕后背景】** ——
    否则 4B 不知道这件事到底是怎么回事，只能硬对文本，判定随意。
  - 护栏：system 硬性要求**只认本轮叙事里明确演出来的结果**，背景只用于理解里程碑的“及格线”，
    **不得因背景写了就判完成**（防 4B 把「预定结局」当成本轮已发生）。
- 某任务里程碑**全部完成** → 代码异步触发**旁路大模型**（`quest_arbiter.arbitrate_milestones_async`），
  **并把该任务的 `真相` 与 `预定结局` 一并喂给它**：
  - 还没到预定结局 / 还有下文 → `需要补充=是`，补 1-3 条新里程碑（任务继续，进行中）；
  - 预定结局已达成 → `需要补充=否`，才算**真正完成** → 归档 + 静默发技能点。
  - 无论哪种，都顺手给一句**玩家可见的 `结果`**（一句话，不剧透真相）。
- **防死循环**：`配置/任务.json.里程碑扩展上限`（默认 3），到顶直接收束；裁定失败/异常 → 机械了结。
- 与 DDL 同一个角色、同一口径（"完成"是**裁定**，不是数数）。
- **异步回传**：完成/续接/过期都 `ui_events.push(kind:"quest")`；
  下一次 `/action`（或 `/state` 的 `_ui_events`）由 `ui_events.drain()` 携回前端。
- **GM 提示**：任务了结（完成/过期）会进 `quest.pending_notes()`，下一轮以
  「===== 世界变动（请据此叙述）=====」注入 GM 一次（不暴露任务系统）。

### 事件真相（跟任务绑定 · 仅 GM 可见）【已定】

- **在 add 那一刻由旁路大模型定死**，跟任务绑定：
  - `真相`：这件事客观到底怎么回事（谁在骗、人在哪、真因）。
  - `结局`：预定走向 / 落点（成功时大致如何收束）。
  - `知情者`：知道真相的人（正式姓名）——将来「信息边界」的种子。
  - `揭示节奏`：如何逐步让玩家接近真相（先露什么、何时松口，**不得一见面说破**）。
- **注入**：只注入**玩家追踪的进行中任务**的真相；GM 上下文里单列一块「事件真相」（**不是任务列表**）。
- **玩家永远看不到**：`player_view`（`GET /quests`）只回 标题/描述/里程碑/时限/结果；
  不含 `真相/结局/知情者/揭示节奏/失败后果`。
- 与 `失败后果` 的分工：`结局` = 成功时预定走向；`失败后果` = 未完成时世界怎么变（DDL 用）。

### 奖励 【已定】

- **物质上只给技能点**：`complete_quest` → 代码静默 `skill_tree.add_point(n, "任务")`。
- **GM 不参与、不知道**（不进上下文、不进叙事）。
- 额度来源：`配置/任务.json` 的默认（如按里程碑数/类型）。
- **NPC 反应另算**：不是任务奖励 —— 走**好感度**（存档结算）+ GM 叙事里的回礼（`add_item`/`modify_money`，属叙事）。

### 前端

- 菜单新增 **「任务」按钮** → 全量列表（**无并发上限**）。
- 每条任务一个 **「追踪」开关**：玩家自选哪几条渲染在游戏页面（HUD 小追踪条）。
- HUD 追踪条：标题 + **时限倒计时**（复用 `/clock` 锚点本地插值，与古钟同套）。
- 状态四色：进行中 / 已完成 / **已过期** / 归档。
- 「已了结」归档区可回望（余韵）。
- **追踪偏好存 localStorage**（纯前端偏好，不污染游戏状态）。

## 五、角色分工（更新后）

| 角色 | 职责 |
|---|---|
| **你（作者）** | 写**初始任务**（直接写在 `游戏数据/任务.json`；时限用相对「时限时辰」，开局由代码换算） |
| **玩家** | 决定「任务化」（建任务）、决定「追踪」哪几条 |
| **旁路大模型（DeepSeek·任务裁定）** | `add_quest` 建任务并**定死 真相/结局/知情者/揭示节奏**；**里程碑耗尽时裁定**补里程碑 / 算完成；DDL 到期给结局 |
| **里程碑判定模型（默认远端·`remote_model`）** | 仅对**追踪任务**报「本轮新做到了哪些里程碑」（并列、可多条）；给 `描述`+里程碑现状+`真相/结局`（背景、硬护栏）——**不判完成**。默认走 `配置/小模型.json` 的远端强模型（Codex 网关，如 `gpt-6-luna`）；`provider=local` 时回退 LM Studio 4B |
| **GM** | 只叙事；上下文里拿到**可见任务投影** + 过期提醒 |
| **代码** | 追踪过滤、里程碑落库、全完成→触发裁定、DDL 判定、静默发技能点、保活集维护 |
| **导演（GLM）** | 弧的形状与相位（上层，本文未细化） |
| **存档管线（大模型）** | **好感度结算**（`update_character_archive`） |
