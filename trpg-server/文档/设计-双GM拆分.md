# 设计：双 GM 拆分（叙事 GM / 工具 GM）+ 异步工具日志

> 状态：**【设计待拍板 · 未实现】**。
> 关联：`README/03 §5.4/5.5`、`README/08`（接口）、`trpg-server/文档/设计-画作与后端推送.md`（push 基础设施）。
> 动机：现在一个 GM（DeepSeek）既叙事又扛 24 个工具 schema、还要跑工具循环 —— 分心、占 token、慢。
> 目标：**叙事与工具执行解耦**，让 DeepSeek 专心叙事。

---

## 〇、一句话

**DeepSeek 只负责叙事**（+ 少量只读工具）并写下一串「工具意图」（自然语言）；
**luna 异步把意图落地**，写进**工具日志**；前端渲染日志，玩家可据此找 DeepSeek 再次确认/纠正。

```
玩家输入
  │
  ├─ 叙事GM（DeepSeek，工具={query_nearby, query_place, list_map_kinds, get_character}）
  │    输出：[narration…, chat…, tool(意图列表)]   ← 一轮 LLM，不跑工具循环
  │    后端：narration/chat → 前端立即渲染；tool → 入队
  │
  └─ 工具GM（luna，全 17 个写工具）【异步 · FIFO 单 worker】
       读：意图 + 当前状态 → 调工具落地
       写：① 实际状态变更（钱/背包/时间/位置/…）
           ② 工具日志（本轮意图 → 调了哪些工具 → 成功/失败）
       产出：UI 事件（battle/art/…）+ 完成通知
             → 入 push 队列 → 前端轮询 GET /pending 渲染
```

## 一、两个 GM 的边界

| | 叙事 GM（DeepSeek） | 工具 GM（luna） |
|---|---|---|
| 职责 | narration / chat；写「工具意图」 | 把意图落成真实状态变更 |
| 工具 | **只读 6 个**（见下） | **写 17 + 状态读 3 = 20 个** |
| 时间 | **不给时间工具**（叙事里可写「过了两个时辰」，落地交工具GM） | `advance_time`/`update_time`/`sleep` |
| 输出 | 不出工具调用，只出 JSON 指令（含 `tool` 字段） | 只出工具调用，**禁止叙事** |

**【已定·方案 B】叙事GM 的 6 个只读工具**（读归叙事）：
`query_nearby` `query_place` `list_map_kinds`（空间库）+ `get_character`（NPC 档案）+ `get_ability`（属性不在状态块里）+ `DB_query_tool`（长期记忆检索；`get_character` 的提示也依赖它）。

**【已定】工具GM 的 20 个**（写归工具）：
17 个写工具（钱/背包/状态/时间/位置/天气/设施/骰子/开战/作画）
+ 状态读 3 个（`get_money` `get_inventory` `get_state`，供其校验）。

> 不含：`get_money`/`get_inventory`/`get_state` **不给叙事GM**（数据已在每轮注入的状态块里）。
> 6 + 20 = 26，刚好覆盖全部工具。

> 叙事 GM 保留 `get_character` 是必需的：**保活**只覆盖近 3 轮说过话的人，新登场的 NPC 必须查档案才能演。

## 二、`tool` 字段：**参数级轻格式**（一行一动作）

实测（`开发/` 探针）：
- **纯自然语言一整句** → 会漏项（「花三文买了壶酒」两边都漏 `add_item`）；
- **一行一动作** → 9B/luna 都能逐条落（多步 3 件全对）；
- luna **开思考**（`reasoning_effort:"high"`）能把多步补齐；9B 不带语义参数时会崩（作画 20.9s 无输出）。

所以 `tool` 字段规定为**动作列表，每行一个动作，参数写全**：

```jsonc
{"type": "tool", "content": [
  "金钱 -3 文（买一壶酒）",
  "背包 +酒壶 ×1",
  "移步 城南酒铺"
]}
```

- 内容类工具**必须把语义参数写进意图**（工具GM 不替你编）：
  `"委托作画《寒江独钓》：画面=孤舟蓑笠翁，寓意=盼归，风格=水墨"`
- 工具GM 只做「意图 → 工具调用」的翻译，不发明内容。

## 三、工具日志（新文件）

| | |
|---|---|
| 存储 | `sessions/工具日志.jsonl`（全过程，逐行，审计用）+ `游戏数据/工具日志.json`（近 N 条，供 GM 与前端） |
| 一条记录 | `{轮, 时间(游戏), 意图:[…], 调用:[{工具, 参数, 结果}], 状态:"已完成/部分失败/失败", 摘要}` |
| 前端 | 菜单/按钮开一个「日志」面板（像历史记录），逐轮显示「意图 → 实际落地」；也可选在对话流里插一行 `（系统：金钱 -3 文；背包 +酒壶）` |
| 玩家纠错 | 玩家对 DeepSeek 说「刚才那笔账不对」→ DS 看得到最近日志 → 写出纠正意图（如「金钱 +3 文（退回多扣）」）→ 工具GM 异步落地 |

## 四、未落地意图的可见性（关键）

异步意味着：**玩家可能在 luna 还没落完上一轮时又行动**。若不处理，DeepSeek 会按「钱还没扣」的旧状态再花一次。

做法（复用「作画中」注入那套）：
- 工具GM 队列里**未完成**的意图，每轮注入 DeepSeek 上下文：
  `===== 尚未落地的操作（工具GM 正在处理）=====\n- 金钱 -3 文（买酒）\n（叙述时按「已发生」处理，不要重复）`
- 落完后清掉。这样叙事与异步落地**不打架**。

顺序：工具GM 用**单 worker + FIFO**（同 `quest_sim` 的做法），保证同回合意图按序落、跨回合不重排。

---

## 五、状态一致性（要说清的代价）

- 叙述先出、状态后落 → `/state`（钱/背包面板）会**滞后一两秒到十几秒**（luna 开思考 3~13s）。
- 若 luna 执行**失败**（如余额不足），叙述里的「已成交」就与事实不符 → **靠工具日志暴露 + 玩家可纠错**。
- 大多数情况 DS 状态块里有真实数值，不会叙述买不起的东西；失败是少数。

---

## 六、存档 / 历史如何记录异步工具

现在 `current.jsonl` 每轮记 `tool_calls`（由 GM 那轮产生）。拆开后工具由 luna 在**另一轮**落地 → 需把日志里的工具调用**回填**到对应回合，或让存档誊写直接读**工具日志**。`save_pipeline._render_tools` 改读工具日志即可。

---

## 七、门禁（guards）迁移

时间权威 / 位置权威 / 台词·场外护栏 / 进食门禁 / 天气门禁 / 金钱只扣一次 —— 全部从「GM 的工具调用」迁到**工具GM**：
- 台词/场外回合（say/gm/observe）本来就禁止改状态 → 现在直接**不让叙事GM 产出 tool 意图**（或产出了也不派给工具GM）。
- 时间/位置权威：把「叙述了移动/时间但没落库」改为「叙述 vs 工具日志」的比对，落库迟到不算漏。

---

## 八、并发 / 失败 / 回退

- 工具GM 与叙事GM **不共享**回合锁：叙事GM 走原 `TurnRunner` 回合；工具GM 走后台 worker（同 `quest_sim` 的 `push` 通道）。
- luna 失败/网关挂：**意图留在队列重试**；N 次失败 → 记 `失败` 日志 + 注入 DS「某项未能落地」。
- 可选回退：机械类意图走本地 **9B**（1.4~3.8s），内容类走 luna —— 但多一层路由，先不做。

## 九、延迟账（实测）

| | 现在（单 GM） | 拆分后（异步） |
|---|---|---|
| DeepSeek | 1~4 轮 × 1.7s = **1.7~6.8s** | **1 轮 ≈ 1s**（瘦身到 4 工具几乎不再省，省的是**循环**） |
| 工具 | 含在上面 | luna 3~13s（**后台，不占回合**） |
| **玩家体感** | 等 2~7s 才见字 | **~1s 就见字**，状态/日志随后到 |

→ 异步后**体感更快**（叙事先到），代价是状态滞后 + 多一次 luna 调用（吃 Codex 额度）。

## 十五、方案调整：叙事即意图（2026-09-26）【✅ 已改】

实测发现：让 DS 写「参数级工具意图」**强迫它思考**、且**不稳定**（时有时无；受伤等用例 3/3 漏）。
改为更干净的分工：

> **DS 只叙事（不输出 tool 字段）；luna 读 DS 的整段叙事，自己判断并调工具。**

- **DS 侧**：不再注入 `_TOOL_INTENT_CREED`；改成一句「你不需要输出 tool 字段，后台会读你的叙事处理」。
  （实测 DS 快了不少：买酒 14.5→9.3s、闲聊 10.3→4.4s，叙事也更长更专注。）
- **luna 侧**：`tool_gm.submit(叙事)`；提示词改为「读叙事→判断变更→调工具」，并加护栏：
  只处理**明确发生**的事（闲聊不调）、**时间只在叙事写明时**才动、拿不准宁可不动。
- 实测：luna 从「梁峰…买一壶酒…揣进怀里」能同时调 `modify_money` + `add_item`。
- 风险：luna 仍会漏（受伤）或误判（闲聊→`advance_time`）——已加规则缓解，且**工具日志可见、可纠错**。

**叙事GM 工具再精简**：6→**4**（去掉 `query_place` / `list_map_kinds`，它们被反复调用、每轮多跑）。
配合「附近实名地点优先直接用」规则，实测**叙事GM 工具轮数 2~4 → 1 轮**。

> 旧的 `two_gm.record_intents` / `sessions/工具意图.jsonl` 已闲置（保留未删）。

3. **放弃本轮 / 重开新局 的异步清理**：`GameSession._clear_async_queues()` 在回滚**之前**统一停掉
